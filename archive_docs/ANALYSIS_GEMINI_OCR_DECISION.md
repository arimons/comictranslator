## 상황 정리

당신의 질문: "Gemini OCR에 cluster의 bbox 외에 검출 text까지 전달하지? 전달받은 텍스트에 Gemini OCR이 굴복한 것처럼 보인다"

**당신의 지적이 맞습니다.** 하지만 역설적으로, **텍스트를 제거하면 정확도가 더 떨어집니다.**

- 🎯 결국 더 많은 후처리 필요

## 원인 분석: 왜 V2가 더 나쁜가?

### 1. Gemini의 특성

**Gemini는 멀티모달 LLM입니다:**
- 이미지와 텍스트를 **함께** 처리할 때 강함
- 텍스트 정보가 **컨텍스트**가 됨 (힌트, 구조 정보)
- 개별 이미지 픽셀만 보면 작은 텍스트 인식 어려움

**예시:**
```
입력: "이것은 만화이고, 다음은 감지된 텍스트"
+ "囲まれて, しまった様だな・・・"
→ Gemini: "아, 긴 대사구나" → 문맥 이해 → 번역 품질 높음

입력: "이 이미지의 위치 (1019, 169)에 텍스트가 있다"
+ [작은 이미지 영역]
→ Gemini: "뭐가 있는지 모르겠네?" → (불명확)
```

### 2. CV API의 강점

Cloud Vision API는 **픽셀 기반 정확도**에 특화:
- 문자 단위 bbox 정확 (±1-2 픽셀)
- 개별 글자 인식 정확도 높음
- 하지만 컨텍스트 이해 못함

### 3. Gemini의 역할

Gemini는 **컨텍스트 이해와 번역**에 특화:
- CV 결과를 읽고 이해
- 오류 교정 (CV 실수한 부분)
- 문맥에 맞는 번역

## "농" 오류의 진정한 원인

```
CV API 결과:     農 (잘못된 인식)
↓ Gemini에 전달
Gemini 프롬프트: "다음은 CV 감지 텍스트입니다: 農"
                 "검증하고 수정해주세요"
↓
Gemini 생각:     "농? 이미지를 다시 보니... 농인 것 같은데?"
                 (프롬프트의 '농'이 시각적 힌트가 됨)
↓ 결과
Gemini 출력:     農 (수정 안 함)
```

**문제:**
- Gemini가 CV 텍스트를 **이미지 증거**로 생각함
- 프롬프트에 명시된 텍스트가 강력한 힌트
- "검증하세요"라고 해도 이미지보다 텍스트를 더 신뢰
