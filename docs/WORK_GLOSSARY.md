# 작품 메모와 화자 지정

번역 문맥을 살리기 위한 참고 정보다. 근거 인용·검토 상태·버전 관리는 두지 않는다. 사용자가 고친 표가 곧 기준이다.

## 작품 메모

프로젝트명 옆 작품 메모 버튼으로 연다. 같은 작품의 여러 권은 하나의 메모를 함께 쓴다.

| 구역 | 필드 | 쓰임 |
|---|---|---|
| 등장인물 | 이름, 원문, 호칭·약칭, 성격, 말투, 주인공 | 이름 표기 통일, 화자별 어투 |
| 고유 용어 | 원문, 한국어, 메모 | 가문·지명·기술 등 표기 통일 |
| 작품 메모 | 자유 텍스트 | 배경·호칭 규칙 등 |

- 저장: `~/ComicTranslator/glossaries/{work_id}.json`, `format: "work-memo-v1"`. 프로젝트 연결은 `work/glossary_binding.json`.
- 주인공은 한 명이며 저장할 때 표 맨 앞(1번)으로 올라간다. 표 순서가 화자 단축키 순서다. 키 칸 드롭다운에서 2-8이나 9(기타)를 고르면 그 자리로 옮긴다. 표는 자동 저장한다. 입력칸에서 포커스가 빠질 때, 순서·주인공·삭제를 바꿀 때, 창을 닫을 때 저장하며 창 오른쪽 위에 저장 상태를 표시한다.
- 이전 근거 기반 형식(`entries`)은 처음 읽을 때 인물(kind 인물)과 용어(나머지)로 옮긴다. 제외(rejected) 항목은 버리고 원본은 `{work_id}.legacy.json`으로 남긴다.

### URL 초안

공개 HTTPS 문서 한 개(나무위키 등)를 `pipeline/work_sources.py`로 읽어 OpenAI에 한 번 보낸다. 자동 수집이 막히면 본문을 붙여 넣는다.

- 모델은 `pipeline/openai_tasks.py`의 `glossary` 라우팅을 따른다. 짧은 자료는 Luna, 긴 자료는 Sol.
- 결과는 새 인물·용어만 추가한다. 이미 있는 인물은 빈 칸만 채우고 사용자가 쓴 칸은 덮어쓰지 않는다.
- 자료는 한국어·일본어 모두 된다. 같은 인물·용어 판정은 한국어 이름 또는 일본어 원문 표기 중 하나라도 겹치면 같은 것으로 보고, 새로 찾은 원문·호칭 표기는 기존 항목에 덧붙인다. 원문 칸이 빈 기존 인물·용어는 프롬프트에 따로 알려 자료에서 일본어 표기를 찾으면 채우게 한다. 일본어 위키백과는 자동 수집되고, pixiv·니코니코 백과는 자동 접근이 막혀 본문을 붙여 넣어야 한다(2026-10-20 확인).
- 공개 주소 제한(로그인 정보·비표준 포트·내부 IP 거절, 리디렉션 재검증, 2MB·16,000자)은 그대로다.

## CV 자동 연결

연결되지 않은 프로젝트는 앞쪽 12페이지의 저장된 CV 글자에서 각 작품 메모의 원문 표기(인물·용어 `original`, 작품명)가 몇 종류 나오는지 센다(`match_works`). 새 Cloud Vision 요청은 하지 않는다. 공백·가운뎃점·장음은 무시하고 비교한다.

- 1위가 3종류 이상이고 2위의 2배 이상이면 편집기가 자동 연결하고 작품 메모 버튼에 "CV 자동 연결"과 근거 표기를 보여 준다. 틀리면 ‘다른 작품 연결’로 바꾼다.
- 그보다 약하면 연결하지 않고 버튼에 "후보: 작품명?"을 띄운다. 메모 창에서 후보를 눌러 연결한다.
- 조회(GET)는 후보만 계산하고, 연결 기록(`matched_by`, `hits`)은 편집기의 POST가 남긴다.
- 메모 창 맨 위 ‘이 프로젝트의 작품’에서 현재 연결과 근거를 보고, ‘변경’으로 CV 후보·다른 작품 메모·새 작품 등록·작품 없이 진행(`POST /api/glossary/unbind`, `matched_by: none`) 중 하나를 고른다. 작품 없이 진행하면 자동 연결을 다시 하지 않는다.

## 화자 지정

영역 분석 탭에서 R을 선택하고 숫자키로 화자를 지정한다. 새 지정은 `work/speakers/{image_id}.json`의 `by_region`에 저장하며 TG가 없어도 가능하다. 같은 TG에 연결된 서로 다른 R에도 각각 화자를 지정할 수 있다. 기존 `by_tg`는 호환용으로 읽고 R 직접 지정을 우선한다.

| 키 | 동작 |
|---|---|
| `1`-`8` | 작품 메모 n번 인물로 지정 후 다음 경계 기반 영역으로 이동 |
| `9` | 기타: 전체 인물 목록 팝업(검색·↑↓·Enter)에서 골라 지정 |
| `N` | 내레이션(중립 서술체) |
| `0` | 해제 |
| `Tab` / `Shift+Tab` | 다음/이전 영역 선택 |

Step 4 직전에 서버가 현재 `regions.json`과 `by_region`(기존 `by_tg` 호환)을 사용해 R별 화자를 만든다(`page_speakers`).

1. 수동 지정이 있으면 그 인물 또는 내레이션.
2. 없고 텍스트 기반 영역이면 주인공을 기본값으로 보낸다. 프롬프트에 "속마음일 가능성이 높음, 내레이션이면 중립 서술체, 효과음이나 다른 인물 대사면 무시"를 함께 적어 모델이 판단하게 한다.
3. 경계 기반 영역에 지정이 없으면 화자를 보내지 않는다. 모델이 대사와 인물 정보로 판단한다.

## 번역 요청에 붙는 순서

`작품 참고문(인물·용어·메모)` → `화자 지정` → `Additional Translation Prompt`. 실행한 값은 `json/{id}_glossary_snapshot.json`과 `integrated.json`의 `glossary.speakers`에 남는다. 메모나 화자를 바꿔도 기존 번역은 자동으로 다시 실행하지 않는다.


2026-10-20 UI 동기화: 페이지를 이미지 생성 권장에서 기존 CV·영역 분석 방식으로 전환해도 연결된 작품 메모와 생성 후보는 유지한다. 경로 전환은 번역을 실행하지 않으며 이후 OCR/번역의 작품 메모 주입 계약은 동일하다.


R 직접 지정의 키는 처리 기준·검출 경로·범위로 만들며 페이지별 파일 안에서만 쓴다. R 번호가 바뀌거나 TG가 제외돼도 같은 범위/경로면 유지한다. 범위나 검출 경로가 바뀌면 다른 R에 잘못 전달하지 않고 다시 지정해야 한다. 저장 요청에는 R 번호와 현재 key를 함께 보내 재분석 중 바뀐 대상을 검사한다. 지정 해제의 null 값은 예전 TG 지정으로 되돌아가지 않도록 명시적으로 보존한다. 텍스트 기반 미지정의 주인공 기본값 정책은 유지한다.

CV가 놓친 글자는 B/U/E 등으로 수동 R을 만들고 분석 적용한 뒤 R을 직접 선택해 지정한다. CV 원문이 비어 있어도 화자를 지정할 수 있다. TG 제외로 자동 R 자체가 사라졌다면 화자 대상도 없지만, 남아 있는 수동 R에는 계속 지정 가능하다. 화자 변경만으로 유료 번역을 자동 실행하지 않는다.

화자 버튼은 R을 직접 선택한 경우에만 활성화한다. TG만 선택했을 때 임의의 연결 R을 골라 저장하지 않는다. 같은 위치를 다시 클릭하거나 R 번호 라벨/우클릭으로 R을 선택한다.
