# 작품별 번역 용어집

## 편집기에서 사용

1. 프로젝트명 옆의 작품 표시를 클릭하면 후보·검색어·용어집을 함께 확인한다. 연결 전에는 `작품 매칭 중`, `작품 후보 확인`, `작품 검색 중`, `CV 대기` 등을 표시하고, 연결 후에는 작품명과 용어집 조사 상태를 각각 표시한다. 프로젝트 표시명은 작품명과 별도로 편집한다.
2. 앞쪽 3페이지 중 첫 CV 결과에서 제목·작가·영문 표기 단서를 읽는다. 새 Cloud Vision 요청은 하지 않는다. 도메인 워터마크와 숫자 권수는 제외한다. 기존에 확인한 작품 중 제목 조각 3개 이상이 제목의 40% 이상을 덮고 역할명(原作·漫画 등)을 제외한 작가 단서 4글자 이상도 일치하는 후보가 하나뿐이면 그 작품의 용어집을 자동 재사용한다. 여러 후보가 일치하면 사용자에게 선택받는다. 이 비율은 CV 문자열 대조 규칙이며 시각적 품질 판정이나 확률 점수가 아니다.
3. 기존 작품 후보가 없고 CV가 준비됐으면 백그라운드 웹 검색으로 새 후보를 찾는다. 새 웹 후보는 자동 연결하지 않고 사용자가 `이 작품으로 확인 · 연결`을 눌러 확인한다. 공식 제목·작가·출처를 확인한다. CV가 없으면 기다리거나 검색어를 직접 입력할 수 있다.
4. 작품 표시를 클릭한 창에서 `작품 검색어`를 수정하고 `검색어로 웹 재검색`을 누른다. 기존 후보의 검색 인용과 CV 식별 단서를 볼 수 있다. 직접 지정하거나 `기존 작품 용어집 재사용` 목록에서 선택할 수도 있다. 새 작품을 확인할 때까지 이전 연결은 유지되며, 검색 실패·빈 결과가 이전 용어집을 삭제하지 않는다.
5. 새 작품 연결 후 작품 기본 정보와 등장인물·별명·지명·조직·기술명을 별도 조사한다. 용어집의 `적용 중 / 검토 필요 / 제외`를 관리한다. 수동 확정과 제외는 재조사로 덮어쓰지 않는다. 같은 작품 ID를 연결한 모든 프로젝트가 검토 결과를 공유한다.
6. 작품 ID는 최초 생성 후 고정된다. 작가명에 `原作：`·`漫画：`를 붙이거나 저자 순서·구분 문자를 바꾸어 입력해도 제목·판본·작가 집합이 같으면 기존 ID를 재사용한다. 기존 해시 ID는 변경하지 않는다. 서로 다른 제목 별칭이나 작가/판본의 의미가 다르면 임의로 합치지 않으므로 기존 작품 선택 기능으로 연결한다.

페이지 자동분할로 만든 프로젝트도 별도 세션이다. 원본과 같은 작품이면 새 프로젝트에서 기존 작품 용어집을 재사용할 수 있다. 페이지 정리·프로젝트 생성 자체는 용어집 조사나 유료 번역을 시작하지 않는다. 2026-10-20 추가된 페이지 정리·서버 상태 API는 위 용어집 계약을 변경하지 않는다.

## 자동 적용 기준

모델이 제시하는 자신감 점수나 URL 문자열만으로 적용하지 않는다. 다음 조건을 모두 만족해야 `auto`로 적용한다.

- 조사에서 확인한 작품이 사용자가 확인한 작품 정보와 일치한다.
- 원문과 한국어 표기가 **같은 검색 인용 구간**에 명시돼 있다.
- 그 대응을 서로 다른 사이트 두 곳 이상이 뒷받침한다. 하위 도메인은 한 사이트로 센다. 검색 프록시 URL의 경우 API가 제공하는 실제 domain을 사용하며, 실제 사이트를 알 수 없으면 자동 적용 근거로 세지 않는다.
- 조사 결과에 불확실 표시가 없고, 같은 원문의 다른 한국어 표기가 없다.

이는 검색 인용 연결을 확인하는 규칙이며 원문 웹페이지 전체를 별도로 가져와 대조한 보증은 아니다. 서로 다른 사이트가 같은 자료를 재인용했을 가능성도 있다. 적용 목록에서도 출처를 확인하고 제외할 수 있다. 작품 일치가 불확실하면 모든 신규 항목을 검토 대상으로 둔다.

수동 확정·제외 결정은 재조사로 덮어쓰지 않는다. 기존 자동 적용 표기와 새 표기가 충돌하면 해당 원문은 검토로 돌려 번역에서 제외한다. 조사된 작품·관계·말투 요약은 참고 화면에만 표시하며, 자동 번역 프롬프트에는 승인되거나 자동 적용된 원문→한국어 대응만 넣는다. 읽는 법이나 별명은 근거가 있는 개별 대응으로 취급하며 추측으로 확장하지 않는다.

## 실행과 저장

- 기존 `.env`의 `GEMINI_API_KEY`를 사용한다. 검색·구조화 추출에 Gemini API 사용 비용이 발생할 수 있다.
- `GLOSSARY_RESEARCH_MODEL`로 조사 모델을 지정할 수 있다. 기본은 기존 OCR에서도 사용하는 `gemini-3-flash-preview`다. OCR 모델 선택과 별개다.
- 작품 후보 검색에는 사용자 검색어와 첫 CV 페이지의 텍스트 단서를 보낸다. 연결 후 용어집 조사에는 확인한 작품명·작가·판본을 보낸다. 이미지·수동 번역 지시문은 조사에 보내지 않는다.
- 나무위키를 포함한 검색 가능한 출처를 조사한다. 특정 사이트의 본문 수집을 보장하거나 접근 제한을 우회하지 않는다. Google Search가 읽은 콘텐츠와 API 인용 메타데이터를 사용한다.
- Google 검색 제안은 API 응답이 있을 때 격리된 iframe으로 표시한다. 웹 문서·조사 결과를 실행 지시로 취급하지 않는다.
- Gemini의 429 응답은 화면에 조사 할당량 초과로 구분해 표시한다. 일반 생성 요청이 가능해도 Google Search 도구의 한도는 별도로 확인해야 한다.
- 조사 중에는 OCR/번역 시작을 보류한다. 조사 실패는 창에 표시하고 다시 조사할 수 있다. 실패 전의 기존 확정 용어집은 보존한다. 서버 재시작으로 중단된 조사도 다시 조사할 수 있다.
- 재조사는 작품별로 하나만 실행하고, 서버 내 동시 조사 수는 2개로 제한한다. 현재 저장소는 로컬 편집기 단일 서버 프로세스를 전제로 한다.

| 위치 | 내용 |
|---|---|
| `temp_output/v2_glossaries/{work_id}.json` | 작품 정보·용어·인용·수동 결정·조사 상태·버전 |
| `temp_output/v2_sessions/{session}/work/glossary_binding.json` | 확인한 작품 ID |
| `temp_output/v2_sessions/{session}/work/work_match.json` | 후보·검색어·CV 단서·검색 상태 (작품 연결과 별도) |
| `.../work/json/{image}_glossary_snapshot.json` | 해당 페이지 번역에 실제 사용한 용어집 |
| `.../work/json/{image}_integrated.json`의 `glossary` | 사용한 작품 ID·버전·적용 대응 |

한 번의 일괄 OCR/번역은 시작 시 용어집 버전을 고정한다. 조사나 검토 때문에 페이지별 적용 표기가 달라지지 않는다. 용어집 변경으로 기존 번역을 자동 삭제하거나 재실행하지 않는다. 기존 결과에 반영하려면 해당 페이지를 **Force Current** 등으로 다시 번역해야 한다. 현재 연결 범위는 편집기의 일반 OCR/번역 경로이며 CLI와 내보내기 이미지 생성 대체 경로에는 자동으로 주입하지 않는다.

## API

- `GET /api/glossary/{session_id}`: 연결된 용어집·기존 작품 목록·CV 후보 및 검색 상태. 유료 검색을 시작하거나 새 세션을 만들지 않는다.
- `POST /api/glossary/match`: 로컬 CV로 기존 확인 작품 재사용, 또는 후보 검색. `force_web=true`와 `query`로 사용자 검색어 재검색
- `POST /api/glossary/confirm`: 작품 확인·연결. 새 작품은 조사를 시작하며 기존 용어집은 재사용
- `POST /api/glossary/research`: 확인된 작품 재조사
- `POST /api/glossary/review`: 용어 적용·표기 수정·제외. 다른 작품에서 열린 오래된 검토 요청은 거부

## 검증

`tests/test_work_glossary.py`에서 인용 검증·두 사이트 조건·표기 충돌·수동 결정 보존·작품별 재사용·조사 중복 방지·API 호출 구성·번역 프롬프트·배치 버전 고정을 검증한다. 외부 API를 모의 응답으로 대체한다.

화면 점검용 서버는 `PYTHONPATH=. .venv/bin/python proof/src/verify_work_glossary_ui.py`로 실행한다. 가상 작품과 가짜 검색 결과만 사용하며 실제 API 비용은 발생하지 않는다. 실제 작품의 표기 정확도와 번역 품질은 사용자가 확인할 작품으로 별도 비교한다.

연동 참고: [Google Search grounding](https://ai.google.dev/gemini-api/docs/google-search), [공식 Python SDK](https://github.com/googleapis/python-genai).

`tests/test_work_matching.py`는 CV 키워드 정리, 작가 없는 부분 일치와 다중 후보의 자동 연결 방지, Ore 형태 프로젝트의 기존 작품 연결, 이름 변경 독립성, 재검색 실패 시 연결·검색어 보존, 늦은 검색 결과와 확정의 경합을 검증한다. 실제 웹 API는 테스트에서 모의 응답으로 대체한다.
