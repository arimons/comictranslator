# 작품별 번역 용어집

## 편집기에서 사용

1. 프로젝트명 옆 작품명을 클릭한다. 기존 CV 단서와 저장된 작품 목록으로 후보를 확인하며 외부 검색 API는 호출하지 않는다. 새 작품은 제목·작가·판본을 직접 지정한다. 작품 연결만으로 자료 수집이나 OpenAI 요청을 시작하지 않는다.
2. 연결한 작품의 **작품 URL 자료**에 공식 작품 소개·등장인물 소개 등의 HTTPS URL을 넣고 **URL 자료 수집 · 저장**을 누른다. 지정한 문서 한 개만 읽으며 링크를 따라 다른 본문을 수집하지 않는다. 동일 URL은 저장본을 재사용한다.
3. 자동 접근이 제한되거나 동적 화면에서 본문을 읽지 못하면 원문을 확인하고 출처 URL과 필요한 본문을 직접 붙여 넣는다. 이 자료로 만든 용어는 자동 적용하지 않고 검토에 둔다.
4. **저장 자료로 용어 정리**를 누르면 저장한 본문과 작품 정보를 OpenAI 일반 생성에 전달한다. Google Search 도구·유료 검색 API·자동 재시도는 사용하지 않는다. 자료 URL/내용/입력 방식·작품 정보·모델이 같은 성공 결과는 재호출 없이 재사용한다. 자료 수집 시각만 달라져도 내용이 같으면 다시 정리하지 않는다.
5. 적용 중·검토 필요·제외 항목과 출처 구간을 확인한다. 수동 확정·제외는 재정리로 덮어쓰지 않는다. 같은 작품 ID를 연결한 다른 권·프로젝트는 저장 자료와 용어집을 함께 재사용한다.
6. **URL에서 다시 수집**은 명시적으로 원문을 갱신한다. 실패하면 기존 저장 자료와 용어집을 보존한다. 자료를 추가·삭제해도 기존 용어집을 즉시 지우지 않으며, 새 자료는 정리 버튼을 눌러 반영한다. 기존 용어를 없애려면 용어의 제외 기능을 사용한다.

프로젝트 표시명은 작품 ID와 독립적이다. 최초 확인 작품과 제목·판본·작가 집합이 같으면 기존 ID를 재사용한다. 작가 역할명과 이름 순서·구분 문자 차이는 정규화한다. 별칭을 임의로 합치지 않는다. 기존 해시 ID도 유지한다.

앞쪽 3페이지 중 첫 CV 결과를 사용하며 새 Cloud Vision 요청은 하지 않는다. 제목 조각 3개 이상이 제목의 40% 이상을 덮고 작가 단서가 4글자 이상 일치하는 기존 확인 작품이 하나뿐이면 그 작품을 재사용한다. 다중 후보는 선택받는다. 이 규칙은 문자열 대조이며 시각적 품질 판정이나 확률 점수가 아니다. 저장 작품 검색어는 로컬 후보 조회에만 사용한다.

페이지 자동분할로 만든 프로젝트도 별도 세션이다. 원본과 같은 작품이면 기존 용어집을 연결한다. 페이지 정리·프로젝트 생성 자체는 자료 수집·용어 정리·번역을 시작하지 않는다.

## 자료 제한과 출처

- 작품당 문서 최대 6개, 문서당 응답 2MB·본문 16,000자. 넘는 본문은 일부만 저장했다고 표시한다. URL·제목·본문·내용 해시·저장 시각·직접 붙여 넣기 여부를 보관한다.
- 공개 HTTPS의 HTML·일반 텍스트만 지원한다. 로그인 정보가 든 URL, 비표준 포트, 내부 IP와 내부 주소로의 리디렉션은 거절한다. DNS로 확인한 공인 IP에 직접 연결하고 원래 호스트의 TLS 인증서를 검증한다.
- 나무위키 등 특정 사이트의 자동 수집 성공을 보장하지 않는다. HTTP 오류·접근 제한·본문 부족은 표시하며 필요한 본문을 붙여 넣는 경로를 제공한다. 이미지나 수동 번역 지시문은 OpenAI 정리에 보내지 않는다.
- 웹 본문·붙여 넣은 자료·모델 응답은 데이터로 취급한다. 자료 안의 지시는 실행하지 않는다. 모델이 만든 URL 대신 저장된 자료의 구간 번호로만 인용을 연결한다.

## 자동 적용 기준

작품 일치가 확인되고, 원문·한국어 표기가 같은 저장 본문 구간에 명시되며, 서로 다른 사이트 두 곳 이상이 대응을 뒷받침해야 한다. 불확실 표시나 같은 원문의 다른 한국어 표기가 없어야 한다. 직접 붙여 넣은 근거가 포함된 항목은 검토에 둔다. 하위 도메인은 같은 사이트로 센다.

이는 저장 구간의 문자열과 인용을 대조하는 규칙이며 자료의 정확성·사이트 간 독립성을 보장하지 않는다. 일본어 자료만 있고 한국어 대응이 없으면 표기를 새로 만들지 않는다. 작품 일치가 불확실하면 신규 항목 모두 검토에 둔다.

기존 자동 표기와 새 표기가 충돌하면 검토로 돌려 번역에서 제외한다. 수동 확정·제외는 보존한다. 작품·관계·말투 요약은 참고 화면에만 표시하며 자동 번역에는 승인되거나 자동 적용된 원문→한국어 대응만 전달한다.

## API 키와 실행

`.env`에서 **`OPENAI_API_KEY`**를 교체하면 된다. 별도 검색 키는 필요 없다. 서버는 시작할 때 환경을 읽으므로 교체 후 재시작한다. 이 키는 다른 OpenAI OCR·번역 기능도 함께 사용한다. 키를 채팅·커밋에 넣지 않는다.

`GLOSSARY_RESEARCH_MODEL`은 용어 정리 모델의 선택 설정이다. 기본은 `auto`이며 짧은 자료(합계 12,000자 이하·3개 이하)는 `gpt-6-luna`, 긴 다중 자료는 `gpt-6.1-sol`을 선택한다. 분류용 API는 호출하지 않는다. Luna의 JSON 형식이 잘못됐을 때만 Sol에서 1회 더 정리하며, 결제·인증·할당량 오류나 근거 부족은 모델 변경으로 재시도하지 않는다. 사용한 모델과 승격 사유는 `routing`에 기록한다. 모델을 직접 지정하려면 이 변수에 OpenAI GPT 모델명을 넣는다. OCR·번역과 이미지 생성 가이드의 기본은 `gpt-6.1-sol`이다. 검색 비용은 없지만 일반 OpenAI 생성의 토큰 비용·할당량은 적용된다. 429는 **요청량 또는 할당량 제한**으로 표시하고 결제·검색 원인으로 단정하지 않는다. 402는 결제 필요로 따로 표시한다.

정리 실패 시 저장 자료와 기존 확정 용어를 보존한다. 정리 중에는 OCR/번역 시작을 보류하고 수동 편집은 가능하다. 작품당 정리는 한 번만 실행하며 서버 내 동시 정리는 2개로 제한한다. 저장소는 로컬 편집기 단일 서버 프로세스를 전제로 한다.

| 위치 | 내용 |
|---|---|
| `temp_output/v2_glossaries/{work_id}.json` | 작품·자료 sources·용어·인용·수동 결정·정리 입력 해시·버전 |
| `temp_output/v2_sessions/{session}/work/glossary_binding.json` | 연결된 작품 ID |
| `temp_output/v2_sessions/{session}/work/work_match.json` | 로컬 작품 조회 검색어 (이전 웹 검색 상태는 사용하지 않음) |
| `.../work/json/{image}_glossary_snapshot.json` | 번역에 실제 사용한 용어집 |
| `.../work/json/{image}_integrated.json`의 `glossary` | 사용한 작품 ID·버전·적용 대응 |

일괄 번역은 시작 시 용어집 버전을 고정한다. 용어집 변경으로 기존 번역을 삭제하거나 재실행하지 않는다. 변경을 반영하려면 페이지를 다시 번역한다. 연결 범위는 편집기의 일반 OCR/번역이며 CLI와 이미지 생성 대체 경로에는 자동 주입하지 않는다.

## API와 검증

- `GET /api/glossary/{session_id}`: 용어집·자료·기존 작품·로컬 CV 후보. 외부 호출 없음.
- `POST /api/glossary/match`: 로컬 CV·검색어 후보 조회. 과거 `force_web=true` 요청은 거절.
- `POST /api/glossary/confirm`: 작품 확인·연결만 수행.
- `POST /api/glossary/source`: 연결 작품 ID와 URL로 저장본 조회·수집. `text`로 본문 저장, `refresh`로 갱신, `remove`로 삭제. 이전 작품 ID의 요청 거절.
- `POST /api/glossary/research`: 저장 자료 정리. 같은 성공 입력은 재사용.
- `POST /api/glossary/review`: 적용·표기 수정·제외.

`tests/test_work_sources.py`는 본문 추출·내부 주소 및 리디렉션 차단·작품 간 재사용·저장본/정리 결과 재사용·갱신 실패 보존·직접 입력의 자동 적용 방지를 검증한다. `tests/test_work_glossary.py`는 OpenAI 일반 생성·인용·충돌·수동 결정·번역 및 배치 연결을 검증한다. `tests/test_work_matching.py`는 CV·키워드의 로컬 조회와 유료 검색 차단을 검증한다. 테스트의 외부 요청은 모의 응답이다.

SDK 참고: [공식 Python SDK](https://github.com/openai/openai-python).

이미지 생성 요청 준비 시에도 현재 연결된 용어집의 적용 항목·버전을 고정하고, 결과 등록 시 변경 여부를 확인한다. 요청 준비는 자료 수집이나 용어집 조사를 실행하지 않는다. 자세한 계약은 [이미지 생성 연결](IMAGE_GENERATION_REVIEW.md)을 참고한다.
