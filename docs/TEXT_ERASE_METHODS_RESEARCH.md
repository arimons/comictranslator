## 0. 먼저, OpenCV 용어 정리

이 문서를 읽는 데 필요한 최소한의 개념만 정리한다. 기존 코드에 흩어져 있는 파라미터들이 무슨 뜻인지 여기서 확인할 수 있다.

### 마스크 (mask)

"이 픽셀을 건드려라 / 건드리지 마라"를 0과 255로 칠한 흑백 이미지다. 원본과 같은 크기다.
글자 지우기에서는 **글자 획이 있는 자리만 255**여야 이상적이다.

마스크가 실제보다 **크면** 배경까지 지워지고, **작으면** 글자 잔상이 남는다.
지금 파이프라인의 품질 문제는 대부분 이 균형에서 온다.

### 임계값 처리 (threshold)

"이 밝기보다 어두우면 글자로 친다"는 규칙이다.

| 방식 | 동작 | 우리 코드 |
|---|---|---|
| 전역 threshold | 이미지 전체에 하나의 밝기 기준 적용 | `_build_conservative_dark_mask`의 150~170 |
| adaptive threshold | 픽셀 주변 영역의 평균을 기준으로 삼음. 조명/톤이 고르지 않아도 잘 잡힘 | `_build_text_mask`의 `ADAPTIVE_THRESH_GAUSSIAN_C, 31, 12` |

`31`은 "주변 31×31 픽셀을 보고 기준을 정한다", `12`는 "그 평균보다 12만큼 어두워야 글자로 친다"는 뜻이다.

### 모폴로지 (morphology) — dilation / erosion / opening

마스크의 모양을 다듬는 연산이다. 커널(kernel)이라는 작은 사각형을 마스크 위에 굴리면서 처리한다.

- **dilation (팽창)** — 흰 영역을 사방으로 부풀린다. `7x7` 커널이면 **사방 3픽셀씩** 커진다.
  - 쓰는 이유: 글자 경계의 안티에일리어싱(흐릿한 가장자리)까지 덮으려고.
  - 부작용: 얇은 획일수록 상대적 팽창률이 크다. 두께 2px 획에 7x7 dilation을 하면 8px가 되어 **면적이 4배**가 된다.
- **erosion (침식)** — 반대로 흰 영역을 깎는다.
- **opening (열림)** = erosion 다음 dilation. 점 노이즈를 없애면서 원래 크기는 유지한다.
  - 우리 코드의 `MORPH_OPEN, (2,2)`가 이것. 작은 점 얼룩 제거용이다.

> **현재 코드의 핵심 문제 지점**
> `_build_text_mask`는 마지막에 `dilate 7x7`을 건다. 안티에일리어싱을 덮으려는 의도지만,
> 얇은 획에는 과하다. 이게 배경을 함께 지우게 만드는 가장 큰 원인으로 보인다.

### 인페인팅 (inpainting)

마스크로 지정한 구멍을 주변 정보로 메우는 것. 방법론은 아래 1~5장에서 다룬다.

## 1. 업계 수동 작업은 실제로 뭘 하나

스캔레이션(scanlation) 커뮤니티의 표준 작업은 **Clone Stamp(도장 도구)** 다.
질문 주셨던 "주변 픽셀 골라서 인접 픽셀로 지우는" 작업이 바로 이것이다.

MangaHelpers 등에서 공유되는 실제 설정은 다음과 같다.

- **하드 브러시 100%, 사각 브러시** — 부드러운 원형 브러시를 쓰면 스크린톤 망점이 뭉개진다
- **Aligned 모드 켜기** — 클릭을 뗐다 다시 눌러도 같은 자리에서 다시 복사하지 않고 상대 위치를 유지
- **브러시 간격 1%** (기본 25%는 사각 브러시에 너무 큼)
- **Sample: Current & Below** — 위 레이어의 선을 복사하지 않도록
- **항상 새 빈 레이어에 복사**

그리고 가장 중요한 원칙이 이거다.

> 디지털 스크린톤 망점은 대개 **수직, 수평, 또는 45°** 로 정렬돼 있다.
> 그래서 복사할 때 수직선은 수직으로, 수평선은 수평으로 맞춰야 티가 안 난다.

이 문장이 알고리즘적으로 중요하다. **스크린톤이 규칙적인 격자**라는 뜻이고,
그러면 주기와 위상을 추정해서 계산으로 재현할 수 있다는 의미다 (아래 3장).

수작업 흐름은 대상에 따라 갈린다.

| 대상 | 수작업 방법 |
|---|---|
| 스크린톤 위 글자 | 같은 그라데이션 구간에서 톤을 클론 |
| 직선 배경 (건물 등) | 선을 교차점까지 연장한 뒤 이음새를 브러시로 |
| 곡선/옷 주름 | 펜 툴로 다시 그림 |
| 평평한 흰 배경 | 그냥 흰색으로 칠함 |

**시사점: 하나의 만능 방법이 아니라 배경 종류별로 다른 방법을 쓴다.**
우리 코드에 이미 `_classify_inpaint_background()`가 배경을 4종으로 나누고 있으니, 그 분기를 살리는 방향이 업계 관행과도 맞는다.

## 2. 방법론 다섯 갈래

### A. 확산 기반 (Diffusion) — Telea, Navier-Stokes

**원리**: 구멍 가장자리의 픽셀 값을 안쪽으로 번지게 한다. 물감이 스며들듯이.

- OpenCV 내장: `cv2.inpaint(..., cv2.INPAINT_TELEA)` 또는 `INPAINT_NS`
- 우리 코드가 `unboxed_text_detector.py:518`에서 미리보기용으로 이미 쓰고 있다

| 장점 | 단점 |
|---|---|
| 매우 빠름, 의존성 없음 | **텍스처를 만들지 못한다** |
| 얇고 작은 구멍에 깔끔 | 넓은 구멍은 뿌옇게 번짐 |
| 평평한 배경에 최적 | 스크린톤 망점이 사라져 회색 얼룩이 됨 |

**만화 적합도**: 평평한 흰 배경에만. 스크린톤·선화에는 부적합.

### B. 예제 기반 / 패치 복사 (Exemplar-based) — Criminisi, PatchMatch

**원리**: 구멍 주변에서 비슷하게 생긴 패치를 찾아 복사해 붙인다. 채울 순서는 "구조선이 있는 곳부터"로 정한다.

**이게 Clone Stamp의 자동화 버전이다.** 사람이 눈으로 골라 복사하던 걸 유사도 계산으로 대신한다.

| 장점 | 단점 |
|---|---|
| **반복 패턴(스크린톤)에 매우 강함** | 끊긴 선을 이어 그리는 건 약함 |
| 원본 픽셀을 그대로 쓰므로 뭉개짐이 없음 | 패치 탐색 비용 (PatchMatch로 완화) |
| 학습 불필요, 결정적(deterministic) | 소스 영역이 오염돼 있으면 오염을 복사 |

**만화 적합도**: 스크린톤 배경에 가장 유망. 우리 코드의 `screentone_light` 분기에 정확히 대응된다.

### C. 격자 인식 스크린톤 재합성

**원리**: 스크린톤은 일정 주기의 격자다. FFT나 자기상관(autocorrelation)으로 **주기와 각도와 위상**을 추정한 뒤, 구멍 자리에 같은 격자를 다시 찍는다.

연구 쪽에서는 이 방향이 활발하다. 스크린톤을 잠재 공간으로 인코딩하는 ScreenVAE, 다운샘플링 앨리어싱을 단서로 원본 해상도와 톤을 복원하는 방법, 격자 검출을 위한 Hough voting 기반 접근 등이 있다.

| 장점 | 단점 |
|---|---|
| **이론상 가장 깨끗함** (원본과 동일한 격자 재현) | 톤 종류·각도 추정이 틀리면 눈에 확 띔 |
| 넓은 영역도 품질 유지 | 그라데이션 톤은 추가 처리 필요 |
| | 선화가 섞이면 적용 불가 |

**만화 적합도**: 단일 균일 톤 영역에 최적. 구현 난이도는 B보다 높다.

### D. 딥러닝 인페인팅 — LaMa, AOT-GAN, MI-GAN (현재 사용 중)

**원리**: 대량의 이미지로 학습한 신경망이 구멍을 그럴듯하게 채운다. LaMa는 푸리에 합성곱으로 넓은 수용영역을 확보해 큰 구멍에 강하다.

| 장점 | 단점 |
|---|---|
| 넓은 구멍, 복잡한 배경에도 뭔가는 만들어냄 | **자연 사진 학습 → 만화는 도메인 밖** |
| 선화를 어느 정도 이어 그림 | 스크린톤 망점을 회색 평면으로 뭉갬 |
| | 마스크가 크면 품질이 급격히 나빠짐 |

**참고**: 이 분야 대표 오픈소스인 `zyddnys/manga-image-translator`도 `lama_large`를 기본으로 쓰고, `lama_mpe`(빠른 버전)와 SD 기반을 대안으로 둔다. 같은 저자가 **AOT 인페인팅 모델을 만화용으로 별도 공개**해 뒀다. `ogkalu2/comic-translate`도 유사 계열이다. 즉 업계 오픈소스도 우리와 같은 자리에 있고, LaMa 하나로 만족하지 못해 대안을 병행한다.

**만화 적합도**: `mixed_line_art` 같은 어려운 케이스의 fallback으로는 여전히 유효.

### E. 생성 모델 — SD inpainting, gpt-image-2

**원리**: 확산 모델에 마스크와 프롬프트를 주고 다시 그리게 한다.

| 장점 | 단점 |
|---|---|
| 어려운 케이스도 그럴듯하게 처리 | 느리고 비쌈 |
| | 매번 결과가 달라 일관성 없음 |
| | 없던 디테일을 지어냄 |

**만화 적합도**: 전면 적용은 무리. 소수의 실패 케이스만 태우는 fallback.

우리 프로젝트는 이미 `pipeline/openai_image_redraw.py`에 `client.images.edit` 경로를 갖고 있어서, 붙이려면 바로 붙는다.

## 4. 우리 파이프라인에 대한 시사점

### 마스크가 먼저다

어떤 인페인터를 쓰든, **마스크가 정확하지 않으면 결과가 좋아지지 않는다.**
현재 마스크는 "어두운 픽셀"을 찾을 뿐이라 겹쳐진 선화·톤 경계도 함께 잡고, 거기에 `dilate 7x7`이 더해진다.

개선 후보:

1. **획두께 기반 필터** — `font_style_analyzer`가 이미 `cv2.distanceTransform`으로 획두께를 잰다. 글자 획은 두께 분포가 좁고 균일하지만 배경 선화는 다르다. 이 코드를 재활용해 글자 획 대역을 벗어난 성분을 마스크에서 뺄 수 있다. **새로 만들 게 아니라 있는 걸 쓰는 것이라 비용이 낮다.**
2. **등방성 dilation → 소프트 알파 마스크** — 거리 기반으로 경계를 부드럽게 하면 같은 커버리지를 더 작은 면적으로 얻는다.

### 배경 분기를 살린다

`_classify_inpaint_background()`가 이미 `white_flat / screentone_light / dark_bg / mixed_line_art`로 나눈다.
지금은 telea/lama 둘로만 보내는데, 업계 수작업이 대상별로 방법을 바꾸는 것과 같은 구조로 넓히는 게 자연스럽다.

| 배경 분류 | 현재 | 제안 |
|---|---|---|
| `white_flat`, `light_flat` | telea | **단색 채우기** |
| `screentone_light` | lama | **패치 복사 (B)** 또는 격자 재합성 (C) |
| `dark_bg` | lama | 단색 채우기 또는 패치 복사 |
| `mixed_line_art` | lama | LaMa 유지, 실패 시 gpt-image-2 (E) |

### 측정이 안 되고 있다

`_build_text_mask`가 `pre_inpaint_mask_ratio`, `lane_bimodality`, `mask_mode`를 계산하는데
`regions.json`에 저장하지 않는다. `proof/` 산출물 1664개를 스캔한 결과 **기록 0건**이었다.

무엇을 바꾸든 개선 여부를 수치로 볼 수 없으므로, 지표 저장이 선행되어야 한다.

## 5. 권장 순서

```
0. 마스크 품질 지표를 regions.json에 저장    ← 측정 가능하게 만들기
1. 마스크 정밀화 (획두께 필터 + 소프트 마스크)  ← 가장 싸고 효과 큼
2. 배경 분기 확대 (단색 채우기 + 패치 복사)     ← 업계 관행과 동일 구조
3. 남는 어려운 케이스만 D/E 검토
```

0번을 먼저 두는 이유는, 1·2번의 효과를 시각 판단 없이 수치로 확인하기 위해서다.
다만 최종 품질 판단은 눈으로 봐야 하므로 before/after 비교 이미지를 함께 만든다.
