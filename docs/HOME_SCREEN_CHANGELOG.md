# 홈 화면 개선 기록

2026-10-20

진입 화면을 ‘홈 화면’으로 부른다. Figma는 ‘파일 브라우저’, Photoshop은 ‘홈 화면’이라는 이름으로 새 작업과 최근 작업 진입을 제공한다. 이 앱은 새 만화 이미지 불러오기와 프로젝트 이어하기를 중심으로 구성한다.

- 홈의 조작 문구를 한국어로 변경. 앱 제목은 편집기와 동일한 파란색으로 통일했다. 후속 요청에 따라 프로그램 이름은 `Comic Translator Studio`를 유지한다.
- 본문 최대 너비 1280px, 여백을 두고 가운데 정렬. 740px 이하에서는 불러오기 → 작업 준비 → 최근 프로젝트 순으로 세로 배치한다.
- 드롭 영역을 축소하고 파일 선택·폴더 선택을 제공한다. 직접 경로 입력은 펼침 영역으로 이동했다.
- ‘Loaded Files’는 ‘작업할 이미지’로 바꾸고 개수와 분석결과 유무를 먼저 표시한다. 개별 파일 확인·제외는 펼쳐서 사용한다.
- 최근 프로젝트를 불러오기 아래 카드로 배치. 대표 원본, 작품명, 최근 작업 시각, 전체 이미지 수, 분석 산출물 수, 결과 이미지 수를 표시한다.
- 수동 검토 완료를 나타내는 영구 상태는 아직 없다. 결과 이미지가 있다는 이유로 수동 검토 완료로 간주하지 않는다. [후속 할 일](EDITOR_TODO.md)에 별도 기록했다.
- 선택지가 하나뿐인 정렬 UI 삭제. 실제 입력 순서는 기존 `natural_name_key`를 유지하며 **파일명 자연 오름차순**이다. 숫자 1, 2, 10 순서이며 내림차순이 아니다.
- 동시 분석 개수는 고급 설정으로 이동. 기본값 4와 허용 범위 1~12를 유지했다.
- 동작하지 않던 캐시 라디오를 제어 상태로 변경. ‘기존 분석결과 활용’은 `force: false`, ‘처음부터 다시 분석’은 `force: true`를 기존 분석 API에 전달한다. 재분석 실행 전 Cloud Vision API 비용 가능성을 다시 알린다. 번역은 여전히 별도 실행이다.
- 불러오기 시 새 이름이 없으면 폴더명 또는 첫 파일명(확장자 제외, 자연 정렬 기준)을 사용하며, 기존 이름은 유지한다. `source_folder_name`은 선택적인 manifest 메타데이터라 기존 세션도 그대로 열린다.
- 최근 작업 시각은 manifest와 분석·번역·수동 가이드·배경 복원 상태·최종 이미지의 마지막 변경 시각 중 최댓값이다. 사람이 마지막으로 편집한 시각이나 검토 완료 시각을 보장하는 필드가 아니다.
- 최근 프로젝트 집계는 파일 존재와 stat만 확인한다. 대형 JSON 해석·캐시 복원·분석 실행을 유발하지 않는다. 기존 중복 프로젝트 필터 정책은 유지했다.

화면 구현은 `frontend/src/StartScreen.jsx`, 실행 연결은 `frontend/src/App.jsx`, 스타일은 `ui_v2/styles.css`, 최근 프로젝트 요약은 `main_v2.py`의 `session_home_progress`가 담당한다. UI 번들은 기존 프론트엔드 빌드로 갱신한다.

참고: [Figma 파일 브라우저](https://help.figma.com/hc/en-us/articles/14381406380183-Guide-to-the-file-browser), [Photoshop 홈 화면](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/homescreen-overview.html).

검증: 프론트엔드 빌드 성공, 전체 pytest 453개 및 13개 subtest 통과. 320·390·600·740·768·1024·1280·1728px에서 가로 넘침이 없음을 확인했다. 브라우저의 파일 선택·목록 펼치기·기존 결과 활용·재분석 취소/실행·최근 프로젝트 실패/재시도를 API 가로채기로 검증했으며 실제 분석·번역 비용은 발생시키지 않았다. 재현 코드는 `proof/src/check_home_screen.js`에 보존한다.

## 같은 날 후속 수정

- 홈 주소는 `/#home`, 작업 화면 주소는 `/#editor`로 정규화한다. 이전 스크린샷용 `#manual-capture` 같은 hash는 현재 화면명으로 교체한다. 세션 복원용 deep link는 아니며, 새 탭은 홈에서 시작한다.
- 성공적으로 이미지를 불러온 뒤 이름 입력란이 다시 활성화되면 포커스를 옮기고 이름 전체를 선택한다. 사용자가 바로 새 작품명을 입력할 수 있다. 실패·취소·새로 불러온 이미지 0장·백그라운드 재조회 때는 포커스를 빼앗지 않는다.
- 불러오기 전에 사용자가 이름을 적었다면 그 이름 저장이 끝난 뒤 세션을 다시 읽어 자동 기본값과의 경합을 막는다.
- ‘이미지를 먼저 선택하세요’는 입력이 없는 상태에서 시작 버튼이 비활성화된 이유를 나타냈다. 불러오기 영역의 안내와 중복되어 제거했다. 이미지를 고르면 ‘N장 작업 준비’를 표시한다.
- 검증용 Chrome의 각 페이지에 MCP 자동화가 설치한 `filechooser` 리스너가 남아 있었다. 선택 이벤트는 발생하지만 자동화가 OS 파일창을 가로채는 환경이므로, 검증 종료 후 해당 리스너와 파일창 interception을 해제한다. 앱 입력 자체를 다른 파일 접근 방식으로 우회하지 않는다. 폴더·파일 선택 이벤트와 업로드 후 이름 기본값·포커스·선택 범위는 별도 검증 페이지에서 재현한다.

후속 검증: 전체 pytest 457개 및 13개 subtest 통과. 파일·폴더 선택 이벤트, 영문 제목, 홈/편집기 주소, 업로드 완료 후 이름 전체 선택과 포커스를 API 모의 응답으로 검증했다. 사용자는 수동으로 접속한 일반 Chrome에서는 선택창이 열리는 것을 확인했다.
