Comic Translator Pipeline

일본 만화 이미지에서 텍스트를 검출·추출·마스킹하고 한국어로 번역해 원본 레이아웃에 오버레이하는 5단계 파이프라인의 전체 흐름과 내부 로직을 해설합니다.

진입점 run_pipeline.py
모듈 루트 pipeline/
외부 API Cloud Vision · OpenAI 또는 Gemini · LaMa
주요 언어 Python 3.11+

개요

파이프라인은 하나의 만화 페이지 이미지를 입력받아 다음 순서로 처리합니다. Cloud Vision으로 글자 위치를 파악하고, BFS 클러스터링으로 말풍선 단위 그룹(TG)을 만들고, FloodFill로 말풍선 내부를 정확히 검출·마스킹하며, OpenAI가 indexed OCR sheet를 보고 번역하고, 마지막으로 한국어 번역문을 원본 위치에 다시 렌더링합니다.

현재 편집기의 영역 처리 기준은 경계 기반 / 텍스트 기반이며, 화면은 공통 R 번호와 타입 배지를 씁니다. 신규 영역·indexed sheet 기반 integrated JSON에는 processing_basis 파생 필드를 추가합니다. 기존 type·location의 bubble/unboxed, 좌표 키와 캐시는 유지합니다. 아래 알고리즘·모듈 이름의 bubble/unboxed는 호환 이름이며, FloodFill·Edge barrier는 검출 방법입니다.

진입점

run_pipeline.py

CLI 진입점입니다. 단일 이미지든 폴더든 모두 run_batch_images()로 통일해 처리합니다.

# 단일 이미지
python3 run_pipeline.py \
  --input test_image/00031.jpg \
  --output proof/ \
  --work-dir proof/ \
  --force --keep-cache

# 폴더 배치 (병렬 4워커)
python3 run_pipeline.py \
  --input test_image/ \
  --output proof/ \
  --work-dir proof/ \
  --workers 4

pipeline/pipeline_runner.py

실행 엔진입니다. run_single_image()와 run_batch_images() 두 함수로 구성됩니다.

배치 처리 run_batch_images()는 이미지마다 run_single_image()를 ThreadPoolExecutor로 병렬 실행합니다. Step 1(Cloud Vision)도 각 worker에서 이미지 단위로 호출합니다. 예전처럼 최대 9장을 한 장으로 붙여 호출하던 그리드 모드는 없어졌습니다.
단계 실행 방식 (stream_subprocess) 각 단계는 python -m pipeline.* 형태의 별도 subprocess로 실행합니다. stream_subprocess()가 출력을 reader thread로 줄 단위로 읽어 로그 콜백에 넘기므로, 출력이 멈춰도 단계별 timeout이 지켜지고 넘기면 프로세스를 종료합니다. 자식 환경에는 PYTHONUNBUFFERED=1(출력 즉시 전달), PYTHONIOENCODING=utf-8(OS 기본 인코딩과 무관하게 UTF-8), 저장소 루트를 앞에 둔 PYTHONPATH(cwd와 무관하게 pipeline.* import)를 넣습니다. 어느 단계든 0이 아닌 코드로 끝나면 그 이미지는 실패로 처리합니다. app.py도 같은 함수를 씁니다. 추가 프롬프트는 --extra-prompt=값 형식으로 넘겨 -로 시작하는 프롬프트도 옵션으로 오인되지 않게 합니다.

Step 1 · Cloud Vision API

Step 1
이미지 → 단어 bbox 감지

Google Cloud Vision API의 DOCUMENT_TEXT_DETECTION으로 이미지에서 단어 단위 bounding box와 confidence를 추출합니다. (detect_text()는 TEXT_DETECTION이지만 파이프라인에서 쓰지 않습니다. 파이프라인은 cloud_vision_api.py CLI로 이미지마다 detect_document_text()를 호출합니다.)

입력
  • 원본 이미지 .jpg/.png
  • 환경변수 CLOUD_VISION_API_KEY
출력
  • *_cv.json — 단어별 bbox 배열
  • 형식: [{"box_2d": [ymin,xmin,ymax,xmax], "label": "...", "confidence": 1.0}]

이미지 단위 호출

CLI(cloud_vision_api.py <image> <out_json>)는 detect_document_text(preprocess="upscale2x_clahe")를 한 번 호출합니다.

1
2배 확대 + CLAHE 전처리

이미지를 2배로 키우고 그레이스케일 CLAHE로 대비를 보정한 임시 파일을 만들어 API에 보냅니다. 임시 파일은 호출 뒤 지웁니다.

2
REST API 호출

CLOUD_VISION_API_KEY로 DOCUMENT_TEXT_DETECTION을 요청합니다. languageHints는 ["ja", "en"]입니다.

3
bbox를 원본 이미지 좌표로 역변환

확대 배율로 나눠 원본 좌표계로 되돌린 뒤 *_cv.json에 저장합니다.

호출 실패 시 결과 파일을 쓰지 않음 API 호출이 실패하면 CLI는 *_cv.json을 쓰지 않고 exit 1로 끝납니다. 예전처럼 빈 배열을 저장하면 "텍스트 0개"로 보여서, 이후 단계와 app의 전역 CV 캐시가 일시적인 실패를 성공으로 굳혀 버립니다. 연결 오류 메시지에 섞인 API 키는 ***로 가립니다.

Step 2 · Text Grouping

Step 2
단어 bbox → 말풍선 단위 TG(Text Group)

Cloud Vision이 뱉은 단어 수백 개를 말풍선 하나에 대응하는 TG(Text Group)으로 묶습니다. 이 TG가 이후 모든 단계에서 "하나의 번역 단위"로 동작합니다.

TG와 anchor의 관계 TG는 Step 2가 만드는 클러스터 단위입니다. "anchor"라는 개념은 Step 3의 FloodFill에서만 등장합니다. 각 TG의 tight_rect(또는 fallback_rect)가 FloodFill의 시드 탐색 기준점 — 즉 anchor — 이 됩니다. TG 자체는 anchor가 아니라, FloodFill 시 TG가 anchor 역할을 한다는 의미입니다.
입력
  • *_cv.json
  • 이미지 높이 (y_tolerance 계산용)
출력
  • *_text_groups.json
  • 각 TG: text_group_id, tight_rect, fallback_rect, lines, orientation

TextGroupBuilder 4-Pass 알고리즘

Pass 1 Fragment → TextLine — 세로 방향 BFS

같은 X열(x_diff ≤ avg_width × 0.33)의 블록끼리 Y 간격이 y_tolerance(= image_height × 1.5%) 이내면 하나의 line으로 합칩니다. 일본어 세로쓰기 특성상 한 열의 글자를 모두 묶는 단계입니다.

Pass 1.5 Line Fragment Repair → Furigana 필터 — 세로 열 조각 재병합 후 루비 문자 제거

① Line Fragment Repair: Pass 1 이후에도 같은 열이 조각난 경우를 복구합니다. merge_gap(= max(y_tol×3, median_h×3))까지의 간격을 허용하되, 가로 방향 line, 폭 비율 ≥ 2.5 (후리가나 방지 포함), 이웃 말풍선 침범 등 5가지 가드 조건으로 오병합을 방지합니다.

② Furigana 필터 (Repair 후): 인접 line 너비의 60% 이하인 좁은 line을 루비(후리가나)로 간주해 제거합니다. Repair 자체가 폭 비율 가드(≥2.5)로 후리가나 오병합을 방지하므로 필터는 그 이후에 실행됩니다.

Pass 2 TextLine → TextGroup — 4단계 BFS 클러스터링

BFS 근접 조건 (동일 말풍선 판단)
  1. 같은 x열 (x_diff ≤ avg_width × 0.33) + y 간격 ≤ tolerance
  2. 인접 열 (x_diff ≤ avg_width × 2.0) + y_start 정렬
  3. 문장 부호로 끝나는 경우 tolerance × 1.5 완화
  4. 가로쓰기 line끼리는 별도 가로 기준 적용

Pass 3 Cluster Consolidation — 선택적 찢어진 TG 재병합

기본 OFF. Y 범위 겹침 ≥ 50% + X 간격 ≤ avg_width×1.5 조건으로 찢어진 cluster를 최대 3회 반복 병합합니다. 파이프라인에서는 FloodFill anchor 정확도를 위해 OFF로 사용합니다.

TG 정렬 규칙

최종 TG는 우→좌, 위→아래 만화 읽기 순서로 정렬됩니다 (sort: (-tight_rect.x, tight_rect.y)). text_group_id는 이 순서로 1부터 부여됩니다.

Step 3 · 만화 대사 추출

Step 3
TG → 마스킹 이미지 + indexed OCR sheet

TG 위치를 anchor 삼아 FloodFill로 실제 말풍선 외형을 검출하고 흰색으로 마스킹합니다. 텍스트 기반 영역의 글자는 LaMa inpainting으로 배경을 복원합니다. 두 종류의 crop을 모아 OpenAI에 보낼 indexed OCR sheet를 만듭니다.

입력
  • 원본 이미지
  • *_text_groups.json
출력
  • *_masked.jpg — 말풍선 흰색 마스킹 이미지
  • *_indexed_sheet.jpg — 라벨 포함 OCR 시트 (OpenAI 입력)
  • *_regions.json — region 메타 + sheet 좌표
  • *_bubble_vis.jpg — 말풍선 검출 시각화

Step 3 모듈 구조

Step 3 전체는 dialogue_extractor.py의 build_dialogue_sheet() 한 함수 호출로 이루어집니다. 내부에서 bubble_detector.py와 run_masked_vis.py를 순서대로 호출합니다.

내부 호출: flood_split.split_mask_by_inflection_line(), split_mask_by_erosion_components()
내부 호출: edge_barrier_flood_rescue.py (구멍 난 말풍선 구제)

Sub-Step A · 경계 기반 검출 — FloodFill 4단계

P
Probe — TG를 anchor 삼아 FloodFill 시드 탐색

각 TG의 fallback_rect(또는 tight_rect)를 anchor로 삼아, bbox 주변에서 흰 픽셀(임계값 248→242→235→225 순차 완화)을 시드로 찾아 magic-wand 방식으로 연결 영역을 채웁니다. 시드 우선순위: 좌우 바깥 여백 → bbox 중심 근접 → 4방향 가장자리.

V
Validation — 검출 후보 검증

검출기 내부의 bubble_candidate를 검증해 bubble_region으로 승격합니다. 이 호환 이름은 최종 처리 기준과 구분합니다.

  • bimodality ≥ 0.88 flood 내부 흑/백 이중 분포 (배경+글자 구조)
  • shape_score ≥ 0.58 형태 점수 = (solidity / 0.82) × type_round. 충분히 채워진 볼록 형태 판정.
  • adjusted_score ≥ 0.50 bimodality + shape_score 가중 합산값 (최종 통과 기준)

탈락 후보는 삭제 없이 bbox_fallback으로 강등해 Rescue로 넘깁니다.

R
Rescue — 탈락 후보 구제

여러 구제 경로로 재판정합니다.

  • cross-split rescue 비율 초과 anchor를 flood group에 합류
  • high_ratio_bubble_rescued solidity ≥ 0.65 AND bimodality ≥ 0.88
  • Edge Barrier 구멍 난/방사형 말풍선 보조 구제
F
Finalize — 검출기 내부 후보 분류 부여

is_valid = True 확정 이후에만 region_type을 매겨 노이즈 오분류를 방지합니다. 검출기 내부 후보 분류(최종 처리 기준과 별개): in_bubble narration_like noise_like

FloodFill 분할 (flood_split.py)

하나의 flood region에 여러 TG가 포함된 경우, 두 가지 방법으로 분리합니다.

  • Inflection Split — convexity defect 쌍을 찾아 절단선으로 분리. 최소 defect 각도 35°, 절단 폭 비율 ≤ 8% (_SPLIT_MAX_CUT_RATIO=0.08). 재귀 최대 깊이 2. 후보 평가는 해당 flood region 영역만 잘라서 계산합니다(결과는 페이지 전체로 계산했을 때와 같음).
  • Erosion Split (fallback) — 점진적 침식 후 connected component가 분리되면 Voronoi 경계로 TG 할당. 최소 subregion 면적 2000px².

Sub-Step B · 텍스트 기반 글자 지우기

경계 기반 영역에 포함되지 않은 TG를 처리합니다. 말풍선 밖 텍스트뿐 아니라 경계를 확보하기 어려워 이 경로로 넘어온 대상도 포함할 수 있습니다.

1
eligible 필터링

유효한 경계 기반 영역에 이미 포함된 TG, noise, 큰 단독 효과음, 단문자 TG를 제외합니다.

2
인접 TG 클러스터링

가까이 붙은 여러 TG를 하나의 처리 단위로 묶습니다 (_cluster_adjacent_tgs()).

3
텍스트 마스크 생성 + 배경 복잡도 보정

글자 픽셀을 밝기 임계값으로 검출 후 bg_std 비례 extra dilate 적용 (복잡한 배경일수록 마스크를 넓힘).

4
SimpleLama inpainting

텍스트 마스크 영역을 LaMa 모델로 배경 복원합니다. bubble_protect_pad로 말풍선 외곽을 보호해 이중 처리를 방지합니다. Apple Silicon에서는 GPU(MPS)로 돌립니다(LAMA_DEVICE로 바꿀 수 있음). LaMa를 올린 프로세스는 2〜3.7GB를 쓰므로, 병렬 분석에서 동시에 LaMa를 쓰는 프로세스를 LAMA_MAX_PROCESSES개(기본 2)로 제한합니다. 나머지는 자리가 날 때까지 기다립니다.

텍스트 기반 영역의 기본 엔진 기본 엔진은 LaMa입니다(DEFAULT_UNBOXED_INPAINT_ENGINE). Telea는 흰 바탕에서는 깔끔하지만 컬러 무늬나 반투명 말풍선 위에서는 색 덩어리로 뭉개지고, 분류가 어긋나는 경우가 있어 기본에서 뺐습니다. Apple Silicon(MPS)에서 영역 한 곳은 약 0.1〜0.5초입니다. Telea는 영역별로 고정했을 때만 씁니다.
그림 위 글자의 자동 지우기 배경이 선화 섞임이나 어두움으로 분류된 자동 텍스트 기반 영역은 TG 사각형(+8px)을 박스로 보고, 아래 수동 텍스트 기반 영역과 같은 글자 마스크로 지웁니다(_ubox_style_mask_in_roi). 사각형 전체를 지우는 방식은 글자가 잡히지 않을 때만 씁니다.
수동 텍스트 기반 영역 지우기 편집기에서 그린 텍스트 기반 영역은 _apply_manual_ubox_lama()가 따로 처리합니다. 박스 안에서 글자 색 픽셀만 마스크로 잡고, 박스 바깥 24px를 문맥으로 넘깁니다. 박스가 어두우면 흰 글자로 보고 마스크를 6px 넓힙니다. 흰 테두리가 남으면 LaMa가 글자 모양 얼룩을 되살리기 때문입니다. 엔진은 기본 LaMa이고, guidance에 inpaint_engine: "lama" 또는 "telea"가 있으면 그 엔진으로 고정합니다. 자동·수동 텍스트 기반 영역 모두 영역 키로 LaMa·Telea를 고정할 수 있고(guidance.inpaint_engine_overrides의 engine, _forced_engine_by_key), 쓴 엔진은 영역에 inpaint_engine_used·inpaint_engine_source로 기록됩니다.
검은 배경 말풍선 처리 _erase_bright_text_on_dark()는 dark flood region에서 밝은 글자획만 별도로 LaMa 처리합니다. 일반 흰 배경 마스킹과 역할이 다릅니다.

Sub-Step C · Indexed OCR Sheet 조립

경계 기반 crop과 텍스트 기반 crop을 읽기 순서로 정렬한 뒤 가로로 이어 붙입니다. 각 crop 왼쪽에 R1 TG2,3 / U1 TG5 형태의 라벨 컬럼을 추가해 OpenAI가 region을 식별할 수 있게 합니다.

  • 정렬 기준(2026-10-29, pipeline/reading_order.py): 페이지 이미지에서 칸 사이 흰 여백(거의 완전히 밝은 줄, 3px 이상)을 찾아 칸을 나눈다(가로 여백 먼저 위→아래, 다음 세로 여백 오른쪽→왼쪽, 재귀). 같은 칸 안에서는 y와 상관없이 x 중심이 큰(오른쪽) 영역이 먼저다. 여백이 비스듬해 두 칸이 한 칸으로 합쳐진 경우만, y 중심 간격이 칸 안 평소 간격의 2.5배 이상·페이지 높이 20% 이상이고 그 사이에 칸 폭을 가로지르는 비스듬한 흰 선(98% 이상 밝음, 기울기 폭의 25% 이내)이 실제로 있을 때 위→아래 띠로 나눈다. 분할 조각은 부모 상자를 공유해 source_order·split_order 순으로 붙는다. 펼침면은 오른쪽 쪽을 먼저 끝낸다.
  • R{id} = 경계 기반 영역, U{id} = 텍스트 기반 영역 (OCR sheet 호환 표기; 앱에서는 공통 R 번호와 배지 사용)
  • TG{ids} = 해당 region에 포함된 TG id 목록
  • 출력된 *_regions.json에 sheet_rect(시트 내 x offset)와 bubble_rect/unboxed_rect(원본 좌표)를 모두 기록

모델 선택

Step 4는 모델 이름의 접두어로 제공자를 고릅니다. gpt-*는 OpenAI Responses API, gemini-*는 Gemini generate_content로 보냅니다. 선택지는 gpt-6.1-sol(기본, reasoning low), gpt-6-luna, gemini-3.8-flash, gemini-3.5-flash-lite 네 가지이고, Gemini는 thinking low와 이미지 해상도 medium으로 호출합니다. Gemini를 고르려면 .env에 GEMINI_API_KEY가 필요합니다. CLI 예: run_pipeline.py --ocr-model gpt-6.1-sol. 편집기 OCR 모델 선택에서 나머지 모델을 수동으로 고를 수 있지만, 실제 만화의 OCR·번역 품질은 별도 확인이 필요합니다. 이전 모델의 비교 기록을 새 모델의 품질 보증으로 사용하지 않습니다.

저장 자료의 용어 정리는 pipeline/openai_tasks.py가 길이·자료 수만으로 자동 라우팅합니다. 짧은 자료는 GPT-6 Luna, 긴 다중 자료는 GPT-6.1 Sol이며 분류용 API 호출은 없습니다. 이미지 생성은 전용 gpt-image-2.5-sunburst, 번역·레이아웃 가이드는 GPT-6.1 Sol입니다. 첫 단계 Cloud Vision 좌표 추출은 별도 경로입니다.

OCR 청크 분할 전략

한 페이지에 region이 많으면 OpenAI 한 번에 보내는 대신 여러 청크로 나눠 전송합니다.

  • 목표 청크 크기: OCR_SHEET_TARGET_REGIONS = 5
  • 소프트 상한: SOFT_MAX = 6 (6 이하이면 분할하지 않음)
  • _split_regions_for_ocr_chunks()가 regions 목록을 5개 단위 청크로 분리 → 청크별로 indexed sheet를 생성해 OpenAI 호출
  • 청크 결과를 병합할 때 region_id가 청크별로 1부터 재시작하므로 offset으로 원본 region_id에 매핑

프롬프트 설계 (PACKED_OCR_PROMPT)

OpenAI에게 indexed sheet의 R1, R2 … 라벨을 기준으로 각 region을 순서대로 처리하게 합니다. region_id를 라벨 번호로 사용하도록 강제해 결과 매핑을 단순화합니다.

각 region에 대해 추출하는 필드:

필드설명값 예시
ocr_text일본어 원문 (줄바꿈 \n 유지)"行くぞ！"
text_translated한국어 번역 (가로쓰기)"가자!"
orientation원문 쓰기 방향vertical / horizontal
render_hint글자 형태 기반 약한 렌더링 힌트 (후처리에서 CV로 보정)normal / semibold / bold / impact / serif_emphasis
segments같은 영역 내 시각적으로 분리된 텍스트 블록 (선택)matched_tg_ids, ocr_text, text_translated …
render_hint는 약한 힌트 OpenAI가 반환한 render_hint는 render_hint_raw로 보존되고, font_style_analyzer의 CV 획두께 분석으로 render_hint_final을 재계산합니다. 실제 폰트 선택에는 render_hint_final이 사용됩니다.

CV 기반 render_hint 보정 (font_style_analyzer)

OpenAI OCR 직후 _measure_region_style_features()를 호출해 indexed sheet의 각 crop과 TG line별 획두께를 측정합니다.

1
획두께 측정

cv2.distanceTransform으로 각 글자 획의 최대내접원 반지름 × 2 = stroke_width_px. 70 percentile로 대표값 채택. ink_density(획 면적/bbox 면적), shape_complexity(둘레²/면적)도 함께 계산.

2
페이지 기준선 계산

같은 페이지 전체 region의 stroke_width 하위 35 percentile을 stroke_base로 삼습니다. 굵은 강조 글자가 많아도 normal 기준선이 왜곡되지 않도록 하위 분위수를 사용합니다.

3
weight_ratio 계산

line별: weight_ratio = stroke_width_px / font_size_estimate. 글자 크기가 달라도 획두께 비율로 bold/impact 여부를 판별합니다.

4
render_hint 최종 판정 (_final_render_hint)

weight_ratio · line_stroke_rel · line_width_rel · char_count 조합으로 5종 중 하나 결정.

판정주요 조건
serif_emphasisline_width_rel ≥ 1.65 + line_complexity_rel ≥ 1.35 + char_count ≤ 6
impactweight_ratio ≥ 0.18 + line_density_rel ≥ 1.35
boldweight_ratio ≥ 0.125
semiboldweight_ratio ≥ 0.105
normal그 외

재시도 로직

응답을 region 단위로 검증합니다(collect_valid_ocr_regions). 다음 경우 그 region만 실패로 봅니다.

  • 응답에 region이 없음 (regions.json 기준)
  • ocr_text가 null이거나, 원문이 있는데 text_translated가 비어 있음
  • render_hint가 허용값 밖

통과한 region은 보관하고, 다음 시도에는 실패한 region만 담은 시트를 다시 보냅니다(chunk당 최대 3회). 끝까지 실패한 region은 integrated.json의 missing_region_ids로 남기고 페이지는 성공으로 처리합니다. 렌더는 그 region을 원본으로 두며, 편집기에서 번역을 직접 넣으면 됩니다. region을 하나도 받지 못한 경우(API 키·네트워크 오류 등)에만 페이지를 실패로 둡니다.

스탈레 캐시 무효화 Step 3 산출물(regions.json, indexed_sheet.jpg, text_groups.json)의 mtime이 integrated.json보다 새로우면 강제 재생성합니다. Step 3과 4의 데이터 정합성을 자동으로 유지합니다.

Step 5 · Text Overlay

Step 5
마스킹 이미지 + 번역 → 최종 이미지

마스킹된 이미지 위에 번역문을 말풍선 크기에 맞게 자동으로 레이아웃해 렌더링합니다. DP 줄바꿈 알고리즘과 페이지 폰트 밴드 조화로 균일한 결과물을 냅니다.

입력
  • *_masked.jpg
  • *_integrated.json (render_hint_final, style_features 포함)
  • *_regions.json (mask_centroid, safe_text_rect, split_order, quality_flags)
  • 원본 이미지 (미번역 region 복원용)
  • 폰트 파일 (Fonts/)
출력
  • *_final.jpg

레이아웃 결정 파이프라인

1
bbox 결정 (overlay_bbox_for_cluster)

우선순위: split flood region rect → 공유된 경계 기반 영역의 rect → safe_text_rect 기반 TG-centered rect → cluster bbox. 경계 기반 영역이면 tg_anchored 로직 없이 무조건 bubble_rect를 사용합니다 (절대 치수 차이 15px 이상이면 flood 우선).

같은 버블의 여러 TG가 공간적으로 붙어 있으면 merge_unseparated_shared_segments()로 먼저 합치고, 충분히 떨어져 있으면 text_group_centered_sub_rect()로 TG center 기준 sub-rect에 배치합니다.

2
inner_rect 산출 — 3가지 보정 누적 (inner_rect_for)

① aspect ratio 기반 padding (세로 말풍선/가로 말풍선/일반 3분기).

② round_score 보정: quality_flags의 round=<값>을 파싱. < 0.45이면 직사각형/나레이션박스로 판단해 패딩 축소.

③ split_order 수평 bias: split region이면 split_order=0(우측 조각)→+8% 우측, ≥1(좌측 조각)→-8% 좌측 시프트. 인접 split region 텍스트가 물리적으로 겹치지 않도록 분리합니다.

④ mask_centroid 보정: dialogue_extractor가 계산한 flood mask 픽셀 무게중심과 bbox 기하 중심의 차이의 50%만큼 ix, iy를 이동. 꼬리가 튀어나온 말풍선에서 텍스트가 실제 버블 공간 쪽으로 당겨집니다.

3
목표 줄 수 추정 (estimate_target_lines)

target = round(√(weighted_len × aspect) × 0.92). 짧은 텍스트, 넓은/좁은 박스 등 여러 케이스에 맞게 상하한 조정. 원본 OpenAI \n 줄 수도 하한으로 반영합니다.

4
DP 줄바꿈 (wrap_tokens)

전체 토큰을 라인별로 쪼개는 최적 분할을 DP로 찾습니다. 라인별 weighted length 편차를 최소화하고, 단독으로 서면 어색한 어절("이", "안", "수는 " 등)에 큰 패널티를 부여합니다.

줄 후보의 폭은 같은 시작 토큰에서 한 토큰씩 늘려 가며 잽니다. 폭이 한도를 넘으면 토큰을 더 붙인 후보는 더 넓어지므로 거기서 멈춥니다. 줄바꿈 기준은 그대로 두고 측정 횟수만 줄이는 최적화입니다.

토큰화 (tokenize): 단일 dash(-, —, ―)도 토큰으로 남깁니다. 공백 없이 붙은 dash는 앞 토큰에 붙여서, 줄 끝 dash가 단어와 다른 줄로 떨어지지 않게 합니다.

66% 줄 채움률 강제 보정: target_lines ≥ 3인데 실제 줄 수 / target < 0.66이면 폰트 상한을 70%로 낮춰 재시도해 버블을 더 꽉 채웁니다.

5
페이지 폰트 밴드 조화 (page_font_band)

한 페이지 모든 cluster raw layout 계산 후, 폰트 크기 median 기준 [median-7, median+5] 밴드로 조정. 페이지 격차 14px 초과 시 leveling 한 번 더 적용합니다.

6
세로쓰기 자동 전환 + 효과음 세로쓰기 강제

원본 1줄 + aspect ≥ 2.0 + wlen ≤ 6이면 세로쓰기 레이아웃으로 전환해 더 큰 글자를 얻습니다. 말줄임표가 있는 짧은 텍스트(aspect ≥ 1.45)도 세로쓰기 후보.

should_force_vertical_short_interjection(): CV가 세로 1줄 + render_hint=serif_emphasis + 짧은 가나 효과음(≤4자)이면 무조건 세로쓰기 폴백.

폰트 선택 로직 (render_hint_final 기준)

render_hint_final사용 폰트
normalFreesentation-5Medium.ttf (기본 대화)
semiboldFreesentation-6SemiBold.ttf
boldFreesentation-7Bold.ttf
impactPretendard-Black.otf
serif_emphasisa트랙터.ttf (serif 강조체)

dash 선과 점 run 그리기

대사 앞이나 뒤에 붙은 dash run(단일 - 포함)은 글리프 대신 최소 0.9em 길이의 가로선으로 그립니다. text_size()도 같은 규칙(horizontal_rule_width(), decorative_line_text_width())으로 폭을 재기 때문에, 줄바꿈 판단에 쓴 폭과 실제로 그려진 폭이 어긋나지 않습니다.

글자와 섞인 점 run(･･･, ・・, ..)은 가로쓰기에서도 항상 …로 바꿔 그립니다(점 3개마다 … 1개, 남는 점은 올림). Freesentation 폰트에는 U+FF65·U+30FB 글리프가 없어서 그대로 그리면 점이 보이지 않기 때문입니다. 점만 있는 텍스트나 세로쓰기 줄 끝 점 run은 기존처럼 합성 점으로 직접 그립니다.

텍스트 기반 렌더링 및 원본 보존

텍스트 기반 영역은 배경 alpha에 따라 구분합니다. LaMa 적용 텍스트 기반 영역은 50%, bbox_fallback 텍스트 기반 영역은 50%, dark_background/dark_flood는 UNBOXED_DARK_BG_ALPHA=230 (약 90%) 불투명 검은 배경 + 흰 글씨. 경계 기반 영역은 50% alpha.

원본 보존 처리: 다음 케이스는 번역 렌더링을 건너뛰고 원본 이미지 픽셀을 복원합니다. (_should_preserve_original_cluster()의 판정 조건)

  • cluster에 preserve_original: true가 지정된 경우
  • bubble이라도 원문/번역이 동일한 영문·기호만으로 이뤄진 텍스트 (타이틀 등)
  • dark flood 검증에 실패한 뒤 edge rescue로 잡힌 경계 기반 컬러 라벨 영역

텍스트 기반 영역 보존 판정(_should_preserve_original_unboxed_cluster())은 현재 항상 False라서, 짧은 텍스트 기반 라벨이나 단독 텍스트 기반 효과음 영역도 번역 렌더 대상입니다. 이전의 단독 텍스트 기반 효과음 영역 판정 함수는 호출되지 않아 제거됐습니다.

배경 복원 패치: 편집기 배경 복원 탭에서 확정한 패치가 있으면 pipeline_runner가 --restore-state work_dir/restore/{name}/state.json을 넘깁니다. 렌더 직전 background_restore.apply_restore_patches()가 각 패치를 마스크 안쪽에만 합성합니다. 패치는 PNG라 masked JPEG를 다시 저장하지 않습니다.

미번역 region 복원: restore_untranslated_regions()으로 integrated.json에서 누락된 region을 원본 이미지로 복원해 마스킹 흰 박스가 남지 않도록 합니다.

수동 분할선(S)

dialogue_extractor._split_region_variants가 분할선이 닿은 영역을 나눈다. TG가 하나도 없는 영역(B로 seed만 찍은 말풍선 등)은 선을 그대로 따라 둘로 나눈다(TG 없는 조각 유지). TG가 1개면 선 밖의 TG 없는 쪽을 잘라 다듬고, 2개 이상이면 양쪽에 TG가 나뉠 때만 자른다. 옆 말풍선에 살짝 닿은 선이 그 말풍선을 자르지 않게 하는 규칙이다(2026-10-28).

수동 Region 제외와 fallback

자동 Region의 suppressed_regions 기록은 경계 검출뿐 아니라 원본 anchor_ids와 좌표에 대응하는 텍스트 기반 fallback 후보도 제외합니다. 모든 TG가 제외되면 OCR Region 0개와 원본 마스킹 이미지를 저장합니다. 새 산출물과 guidance 결과 캐시의 region_suppression_version은 1이며, 제외 기록이 있는 옛 결과 캐시는 재사용하지 않습니다. 수동 가이드는 별도 삭제합니다.

페이지별 기존 분석 경로 선택

2026-10-20: 편집기의 기존 방식 전환은 work/page_policy의 analysis_route를 standard로 저장합니다. pipeline_runner는 이 정책을 읽어 Step 3에 --force-standard를 전달하고 표지의 자동 건너뛰기를 우회합니다. 기존 CV는 재사용하고 없을 때만 호출합니다. 표지 건너뛰기 산출물은 재생성하며 공유 기본 분석 캐시와는 섞지 않습니다. UI 전환은 pre_ocr까지만 실행하고 번역·이미지 생성·기존 최종 출력은 변경하지 않습니다.

R 직접 제외와 화자 지정

2026-10-20: 새 R 제외 target_key는 범위·검출 방식으로 자동/수동/분할 영역을 식별하며 마스킹 전에 해당 대상만 제외합니다. 구 좌표 기반 제외도 읽습니다. 화자는 페이지별 by_region 기록이 우선하고 기존 by_tg를 호환용으로 읽습니다. CV anchor 없는 수동 R도 지정할 수 있고 Step 4 프롬프트로 연결됩니다. R 번호나 anchor 변경만으로는 같은 범위의 지정을 잃지 않으며 범위/경로 변경 시 재지정합니다.
