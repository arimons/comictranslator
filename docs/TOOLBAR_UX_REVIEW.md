# 영역 분석 도구 모음 검토와 변경

2026-10-20. 삭제는 화면에 즉시 반영하고, 무거운 재분석은 Cmd/Ctrl+Enter로 모아 실행한다.

## 반영한 변경

- R 제거의 X 단축키와 상시 도구 버튼을 없앴다. 우클릭 메뉴의 **이 처리 영역 제외**로 옮겼다. TG와 R이 겹치면 메뉴에서 TG 제외/R 제외를 직접 고른다. 수동 영역은 가이드 삭제로 처리한다.
- 우클릭 자체는 삭제하지 않는다. 메뉴는 화면 밖으로 잘리지 않으며 Escape·바깥 클릭으로 닫고 방향키로 항목을 고를 수 있다.
- TG를 제외하면 그 상자를 즉시 숨긴다. 모든 연결 TG가 제외된 자동 R도 숨긴다. 일부 TG가 남으면 R 경계는 다음 분석까지 유지한다. R을 제외하면 연결 TG 표시도 숨긴다.
- 삭제한 미적용 편집을 Cmd/Ctrl+Z로 되돌리면 캔버스를 즉시 복원한다. 이 과정은 API·LaMa·Telea를 실행하지 않는다.
- 미적용 변경이 있음을 표시한다. 실제 마스킹·OCR sheet 재생성은 버튼 클릭 또는 Cmd/Ctrl+Enter에서만 실행한다. 일반 Enter는 적용 버튼에 포커스돼 있어도 실행하지 않는다. 현재 페이지에 적용하며 프로젝트 전체 재분석이 아니다.
- 기존 적용 시 Undo 초안 기록을 정리하는 정책은 유지한다. 적용 후 결과 이미지 자체를 버전별로 되돌리는 기능은 이번 범위가 아니다.
- 9개 도구를 8개로 줄이고 역할별 구분선을 넣었다. 문자·이모지 아이콘 대신 같은 굵기의 SVG 선 아이콘을 사용하고 한국어 도구명·단축키를 tooltip에 표시한다.

기존 JSON·제외 기록·캐시 형식은 바꾸지 않는다. UI의 미리보기만 현재 편집 지시를 반영하며, 저장된 분석을 바꾼 것처럼 표시하지 않는다.

## 사용성 판단

주요 문제는 같은 ‘제외’가 TG·R·페이지에 중복된 도구로 보이고, T×·T/·╱·□·●만으로 조작 결과를 알기 어려웠다는 점이다. 페이지 제외는 상단 상태 버튼, TG 제외는 선택 후 D 또는 Delete, R 제외는 해당 영역의 우클릭 명령으로 나누는 구성이 적합하다.

| 역할 | 현재 키 | 아이콘 표현 | 판단 |
|---|---|---|---|
| 선택 | V | 화살표 커서 | 유지 |
| 이동 | H / Space 누른 채 드래그 | 손 | 유지. 잠깐 이동은 Space 우선 |
| TG 제외 | 선택 후 D / Delete | 글자 상자와 빼기 | D는 선택한 TG에만 적용하는 명령이며 모드를 바꾸지 않음 |
| TG 분할 | T | 글자 상자 내부의 분할선 | R 분할과 이름을 함께 표시 |
| Edge 장벽 | E | 벽과 경계에 막힌 화살표 | 글자 입히기의 E 지우개와 다르므로 탭별 이름·아이콘이 중요 |
| 영역 분할 | S | 영역 외곽과 대각 분할선 | Split의 S. 입력 선은 변곡점 탐지의 힌트 |
| 텍스트 기반 영역 | U | 모서리 상자와 T | 과거 Unboxed의 U를 호환 키로 유지 |
| 경계 기반 시작점 | B | 말풍선 외곽과 점 | 점만 있던 아이콘보다 시작점의 목적이 분명 |

Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, Cmd/Ctrl+Enter와 기존 보기 키는 유지한다. 일반 Enter에 무거운 실행을 다시 연결하지 않는다. R 제외에 새로운 전역 단축키도 추가하지 않는다.

사용자 확인으로 L→S를 반영했다. 도구 순서는 **V·H / D·T / E·B·S·U**이다. E·B·S는 경계 기반 검출/분리, U는 텍스트 기반 범위 지정으로 한 묶음에 둔다. V·H는 모드 진입, D는 선택 명령으로 구분하며, 선택한 TG가 없을 때 D 버튼은 비활성화한다. D 키도 포인터 아래 다른 TG나 R을 지우지 않는다. 기존 저장 guidance와 캐시 키는 그대로 유지한다.

## TG BFS와 T / S의 역할

TG 생성은 CV 조각 → TextLine → Repair → BFS 묶음 → 보수적 X방향 확장을 거친다. BFS는 기하 조건의 연결을 순회하므로 A-B, B-C의 연결로 A와 C가 한 TG가 될 수 있다. 픽셀을 채우는 말풍선 FloodFill과 구분한다.

T는 선택 TG의 fragment 중심점을 사용자 직선의 양쪽으로 나누는 수동 후처리다. 양쪽이 모두 있어야 성공하며, 오른쪽은 기존 ID, 반대쪽은 새 ID가 된다. 선에서 3px 이내 조각은 manual_orphans로 기록되고 유효 TG에서 빠질 수 있다. 이를 숨기지 않고 매뉴얼에 명시했다. T로 두 TG를 만들어도 같은 R에 연결될 수 있다.

S는 TG가 아닌 처리 영역을 나눈다. 사용자 선을 힌트로 변곡점 쌍을 찾고 실제 분리선으로 보정하며, 불가하면 anchor/사각형 fallback을 시도한다. 단순히 그은 선 그대로 잘리는 기능으로 설명하지 않는다. 두 도구 모두 OCR 후보 단위를 수동 보정한다는 목적은 같다.

## 실제 도구 전후 캡처

`proof/src/capture_tool_examples.py`, `proof/src/capture_tool_examples.cjs`로 별도 프로젝트 `20261020_manual_tools`를 만들고 실제 앱 조작과 동일한 로컬 Step 3을 실행했다. 분석 적용 요청은 검증 스크립트가 격리된 프로젝트의 함수에 전달해 공유 분석 캐시를 쓰지 않는다. 원본 프로젝트는 수정하지 않았다. 추가 유료 분석과 이미지 생성도 없다.

`proof/src/embed_tool_examples.py`가 D·T·E·B·S·U의 조작 전/미적용 가이드/실제 적용 후 캡처를 매뉴얼에 내장한다. D의 Cmd+Z 복원 화면도 포함했다. 촬영은 조작 검증 예시이며 시각 판정의 정답 데이터가 아니다.

관찰 결과: D는 TG 8→7개, T는 8→9개지만 TG7·TG9가 같은 R에 연결되어 R은 7개를 유지했다. B는 manual_bubble_seed_rescue, E는 manual_edge_barrier_rescue, U는 manual_ubox_guide 경로를 확인했다. S는 TG 12개를 유지하면서 R 11→12개가 됐고, 해당 샘플은 manual_split_rect_fallback 경로이므로 변곡점 분할 성공 사례로 소개하지 않는다.

## 오른쪽 영역 편집 패널 간소화

기본 노출을 분석 적용, 미적용 상태, 실행 취소/다시 실행, 선택한 영역의 화자 지정으로 줄였다. 미선택 상태에는 비활성 화자 버튼 대신 짧은 선택 안내를 표시한다. 기존 Selection의 Off/On은 D/실행 취소와 중복돼 없앴다. 기능 자체의 제외·복원은 기존 조작으로 유지한다.

레이어는 겹친 표시 확인에 유용하므로 ‘표시 설정’으로 접었다. 편집 내역도 접으며 텍스트 기반 영역의 LaMa 강제 선택은 내역에서 계속 사용할 수 있다. JSON은 ‘고급 편집·초기화 → 가이드 JSON 직접 편집’ 안으로 옮겼다.

Clear Unsaved는 미적용 변경만 버리는 동작이 아니었다. 저장된 가이드도 포함해 화면 전체를 비우는 기존 동작을 그대로 두고 ‘가이드 전체 비우기’로 이름과 설명을 바로잡았다. 분석 적용 전에는 저장 산출물에 영향이 없고 실행 취소할 수 있다. Delete Outputs는 가이드·분석·번역·최종 이미지까지 지우므로 ‘이 페이지 작업 결과 삭제’로 옮기고 실제 삭제 전 확인/취소를 제공한다. 원본·CV·TG·이미지 생성 후보는 유지한다. 두 초기화 동작 모두 기본 화면에 상시 노출하지 않는다.

검증: `proof/src/check_guidance_sidebar.js`를 별도 headless로 실행해 기본 접힘, 선택 후 화자 표시, 표시 설정, JSON 편집, 가이드 비우기/실행 취소, 삭제 확인/취소를 점검한다. fixture만 편집하고 실제 서버 분석·저장·삭제 요청은 보내지 않는다.

패널 변경 검증 결과: 전체 pytest 499개·하위 검사 13개 통과. 별도 headless로 패널 동작과 기존 삭제/실행 취소/명시적 적용을 검사했다. 비교 탭이 두 줄로 줄바꿈될 때 확대 도구와 겹치던 제목 행 높이도 함께 수정했다.


## 캔버스 높이 확보와 선택 영역 문맥

일반 페이지에도 보이던 이미지 생성 검토 안내와 페이지 처리 상태의 전폭 행을 제거했다. 페이지 제외/복원은 오른쪽 패널의 작은 버튼으로 옮겼고, 이미지 생성 배지는 recommended/optional 판단 또는 등록 결과가 있는 경우에만 같은 자리에 표시한다. 판단/결과가 없는 일반 페이지에는 생성 안내를 렌더링하지 않는다. 생성 결과/권장 페이지의 비교 동작과 복원 기능은 유지한다.

처리 영역 R은 기존 처리 기준 색으로 옅게 채운다. contour가 있으면 해당 외곽 내부, 없으면 기존 bbox를 채운다. 선택 시 농도를 높이고, 표시 설정에서 R을 끄면 색칠도 숨긴다. 검출·분류·마스크 자체는 변경하지 않는다.

오른쪽 화자 지정에 선택 R의 anchor TG들을 연결한 읽기 전용 CV 원문과 현재 화자 label을 표시한다. 유효 TG가 있으면 그 텍스트를 사용하며 번역 결과를 CV 원문처럼 표시하지 않는다. 아직 R이 없는 TG도 선택하면 해당 텍스트를 볼 수 있다. 인식 오류 가능성을 표시한다.

Headless 검사에서 일반 페이지 생성 안내 미노출, 1000px 높이 창의 캔버스 높이 800px 이상 확보, 선택 R의 색칠 픽셀, CV 읽기 전용, 화자 지정과 기존 생성 결과 표시/분석 전환을 확인한다. 검증용 응답만 편집하고 실제 프로젝트의 유료 분석·저장·삭제는 실행하지 않는다.

세 색 구분도 복원했다. 기존 글자 입히기의 공통 팔레트를 영역 분석에서도 사용한다. 일반 Bubble은 파랑(#38bdf8), Edge는 초록(#22c55e), Unboxed는 노랑(#eab308)이다. 원문이 보이도록 기본 채움 약 9%, 선택 약 17%의 알파를 사용하고 기존 도형 opacity와 합성된다. Edge는 세 번째 처리 기준이 아니라 경계 기반의 검출 경로이며 source_method/method/quality_flags를 기존 usesEdgeBarrier로 읽는다. 오른쪽에 처리 기준과 검출 방식 label을 함께 표시한다. 색상·투명도 계약은 `proof/src/check_region_colors.js`에서 실제 캔버스 픽셀로 확인한다.
