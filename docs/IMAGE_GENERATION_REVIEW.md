# 이미지 생성 권장과 결과 등록

2026-10-20. 편집기의 1차 권장 표시와 Codex 내장 이미지 생성 결과를 페이지에 연결하는 경로.

## 실행 흐름

1. MCP로 원본을 관찰한 뒤 `recommend_image_generation`에 근거와 수준을 저장한다. 편집기에 **이미지 생성 권장 / 이미지 생성 선택** 배지가 표시된다. 범용 자동 분류기는 아직 없으며, 권장은 자동 실행이 아니다. 시각적 판단 기준은 사용자에게 확인한다.
2. 사용자가 생성을 요청하면 `prepare_image_generation`으로 원본·현재 페이지 revision·연결된 작품 메모(인물·용어, 작품 없이 진행한 프로젝트는 비어 있음)와 마지막 저장 시각·기존 번역·추가 지시를 고정한다. 이 도구는 생성하지 않는다. 편집기 서버를 재시작하는 동안(`POST /api/server/restart`)은 준비·등록 요청도 잠시 응답하지 않으므로 다시 시도한다.
3. 에이전트가 반환된 원본과 프롬프트를 **호스트의 내장 이미지 생성 도구**에 전달한다. 앱이 Codex OAuth 토큰을 가져오거나 자체 모델 API를 호출하는 방식이 아니다. 특정 모델명을 프롬프트에 적었다는 이유로 실제 모델을 기록하지 않는다.
4. `register_generated_image`에 요청 ID와 반환 파일 경로를 전달한다. 앱은 원본·번역·용어집 변경, 이미지 형식·크기·비율을 검사한 뒤 **미검토 생성 후보**로 등록한다.
5. 편집기 배지를 눌러 원본과 생성 후보를 나란히 본다. 후보는 5초 간격으로 새로 읽는다. 이미지의 내용이 올바른 페이지인지, 글자·그림·폰트가 적합한지는 사용자가 확인한다. 등록 자체는 시각적 합격 판정이 아니다.

현재 단계는 **후보 보관·비교까지**다. 생성 후보를 최종 출력으로 채택·복원하는 기능은 후속 작업이며 `output/final`과 기존 입력은 수정하지 않는다. 파이프라인의 OCR/번역/분석도 실행하지 않는다. 생성 자체는 사용자가 요청한 호스트 이미지 생성 도구의 작업이다.

## MCP 계약

기존 조회·관찰 초안 도구는 유지한다. 추가 도구는 다음 네 개다.

| 도구 | 입력/동작 |
|---|---|
| `inspect_image_generation` | 세션·페이지 ID로 권장 근거와 후보 목록 조회 |
| `recommend_image_generation` | 세션·페이지·base_revision·reason·priority(`recommended`, `optional`, `normal`)로 표시 저장 |
| `prepare_image_generation` | 세션·페이지·base_revision·additional_prompt로 요청 생성. 요청 ID·원본 경로·프롬프트·고정 문맥 반환 |
| `register_generated_image` | 세션·페이지·request_id·source_path로 후보 보관. 같은 요청과 동일 반환 파일은 중복 저장하지 않음 |

새 도구 목록은 MCP 클라이언트를 재연결해야 보일 수 있다. 실제 검증은 새 stdio 연결을 열어 수행한다.

반환 파일은 `~/.codex/generated_images/` 또는 저장소 `~/ComicTranslator/inbox/image_generation/` 내부만 읽는다. 생성 도구가 다른 위치에 반환하면 에이전트가 수신 폴더로 복사한 뒤 등록한다. 링크를 따라 허용 폴더 밖을 읽거나 다른 세션·캐시에 결과를 쓰는 동작은 거부한다. 외부 URL 다운로드는 하지 않는다.

생성 요청은 페이지·번역·용어집 내용 해시를 묶는다. 등록 직전 문맥이 달라졌으면 다시 준비해야 한다. 저장 후 문맥이 바뀐 후보는 편집기에서 재검토 대상으로 표시한다. 비율 오차 10% 초과는 등록 거부, 2% 초과는 경고다. 크기·비율을 맞추려고 자동으로 잘라내거나 늘리지 않으며 반환 이미지 해상도를 그대로 보관한다. 이 수치는 형식 검사이며 커버 여부를 판정하는 CV 기준이 아니다.

## 로컬 보관

```text
~/ComicTranslator/projects/{session_id}/work/image_generation/{image_id}/
  recommendation.json
  request-{request_id}.json
  result-{result_id}.json
  result-{result_id}.png
  returned-{result_id}.bin
```

`returned-*.bin`은 생성 도구가 반환한 이미지의 원래 바이트이며, PNG는 앱 표시용이다. 요청에는 원본 SHA-256·작품 메모 저장 시각·번역 문맥과 실제 생성 프롬프트를, 결과에는 페이지 대응·반환 파일 SHA-256·크기·미검토 상태를 기록한다. 모델이 공개되지 않은 내장 생성은 `actual_model: null`로 남긴다.

권장·요청·후보는 프로젝트의 로컬 runtime 폴더 수명을 따른다. Git에 이미지를 커밋하지 않는다. 프로젝트 삭제 시 함께 삭제되므로 장기 보관이 필요하면 프로젝트 전체를 별도로 백업한다.

## AI 글자 지우기와의 차이

이 문서의 생성 결과는 번역까지 그린 페이지 후보다. 영역 분석 탭의 **AI 글자 지우기**(`POST /api/restore/ai-erase`, [파일 맵](CODEBASE_FILE_MAP.md)의 `pipeline/ai_text_erase.py`)는 글자만 지운 배경을 만들고, 확정하면 배경 복원 패치로 저장해 번역은 기존 글자 입히기가 얹는다. 두 결과는 서로 다른 저장 위치를 쓴다.

## 비교 화면과 기존 분석 방식 전환

생성 결과는 최종 output이 아닌 **미검토 후보**로 페이지에 등록된다. 비교 미리보기의 ‘생성 결과’ 탭에서 바로 볼 수 있고, 원본·마스크·최종 출력·OCR 시트와 구분한다. 등록 결과가 없으면 권장 페이지의 비교 영역 안에 눈에 띄는 안내와 기존 방식 전환 버튼을 표시한다. 등록 결과가 있으면 큰 안내 대신 생성 이미지를 기본으로 표시하고, 결과 수·출력 미반영·재검토 상태와 접힌 전환 조작만 한 줄에 둔다. 원본도 계속 볼 수 있다.

‘기존 방식으로 처리 · CV/자동 분석’을 누르면 선택 페이지의 `analysis_route: standard`를 프로젝트 로컬 정책에 저장하고 CV→TG→처리 영역 분석까지만 실행한다. 기존 CV 결과를 우선 재사용하고, 없으면 유료 CV 호출이 발생할 수 있음을 버튼 아래 안내한다. OCR/번역·이미지 생성은 실행하지 않는다. 생성 후보·원본·이전 최종 출력은 보존한다.

`POST /api/page-analysis-route`는 정책만 저장한다. 분석 요청은 UI가 별도 `/api/analyze-stream`으로 한 번 보낸다. 페이지 제외 설정과 경로 선택은 같은 `work/page_policy/{image_id}.json` 안에서 서로를 보존한다. 기존 정책 파일에 경로 키가 없으면 auto로 읽는다. API는 auto 복귀도 허용하지만, UI는 현재 기존 방식 전환만 제공한다. auto는 권장에 따른 기존 동작으로 돌아가는 설정이며 즉시 생성 명령이 아니다.

기존 방식에서는 표지 파일명의 Step 3 건너뛰기를 우회한다. CV 캐시는 계속 재사용하고, 경로 구분이 없는 공유 분석/가이드 산출물 캐시는 읽거나 쓰지 않아 기본 경로와 섞이지 않는다. 기존 표지 건너뛰기 산출물은 다시 분석하며, 이전의 skipped 번역 표지만 정리한다. 일반 번역·최종 이미지는 보존한다.

미리보기는 캐시 이미지의 onLoad와 effect 순서 때문에 치수가 지워지지 않도록 URL별 로드 상태를 유지한다. 실패는 영구 ‘불러오는 중’ 대신 오류·다시 불러오기로 표시한다. 검사: `tests/test_page_analysis_route.py`와 `proof/src/check_generation_entry.js`. 브라우저 검사는 실제 후보를 읽되 유료 분석 POST를 fixture로 가로챈다. 이번 변경 확인 중에는 실제 3권 표지의 CV/번역/이미지 생성을 실행하지 않았다.

UI 검증은 별도 headless Chromium에서 실행한다. `proof/src/run_headless_browser_check.cjs`에 검사 파일을 인자로 전달하며 작업 중인 브라우저 창·탭은 열거나 전환하지 않는다. 표지 원본과 등록된 PNG의 바이트는 이번 UI 변경으로 수정하지 않는다.

일반 페이지의 공통 생성 안내 행은 제거했다. recommended/optional 판단이나 등록 결과가 있는 페이지에만 오른쪽 작업 패널의 작은 생성 배지를 표시한다. 권장 근거와 생성 요청/후보 비교는 배지를 눌러 확인하며, 캔버스 위 전폭 행은 사용하지 않는다.

일반 편집의 화자 저장은 새 R 직접 지정(by_region)을 사용하며 구 TG 지정을 호환한다. 이 변경은 생성 후보를 채택하거나 자동 생성하는 동작을 추가하지 않는다. 수동 R 제외는 범위/검출 방식 키로 해당 R만 제외하고 등록된 생성 결과는 보존한다.
