# Overlay 제자리 텍스트 편집기 (PPT식 WYSIWYG)

2026-11-02 작업 기록. 글자 입히기 탭의 Overlay Result Editor에서 박스를 눌러 번역문을 고치는 방식을 정리한다.

## 사용자 의도 (가장 중요)

- 박스(R 영역)를 누르면 그 영역이 확대되고, **빨간 선택 박스 자체가 텍스트 박스**가 된다. 별도 플로팅 창, 파란 박스, 팝업은 두지 않는다.
- 편집 중 모습과 선택 해제 후 모습이 **같아야 한다**(파워포인트 텍스트 박스). 편집 모드에 들어가도 글자의 위치, 줄바꿈, 크기, 굵기가 움직이거나 달라지면 실패다.
- 글자 크기, 정렬, 가로/세로, 글꼴 스타일 단축 버튼, 글자색은 박스 위 얇은 툴바에 둔다. 외곽선, 폰트 목록 같은 상세 옵션은 오른쪽 패널에 둔다.
- 오른쪽 패널의 Selected Region 카드(번역문 입력란, 좌표, 회전, Merge/Split)는 제거했다. 필요해지면 툴바로 다시 옮긴다.
- 같은 박스 재클릭(글자 없는 곳), Esc, 빈 곳 클릭으로 닫고 전체 보기로 돌아온다. 박스를 누르면 왼쪽 원본 패널도 같은 영역으로 확대된다(`OriginalFocusPane.jsx`).
- 대사 리스트에는 일본어 원문을 기본으로 함께 보인다. 끄면 새 저장 키(`comic-translator-dialogue-original-v2`)에 기억한다.

## 시행착오와 버린 방식

1. 클릭 때 별도 플로팅 편집 창을 띄움 → 폐기. 렌더와 다른 곳에 새 레이아웃을 그리는 것으로 보였다.
2. 빨간 박스에 맞춘 별도 입력 박스와 블러로 기존 글자 가리기 → 폐기. 글자가 이중으로 보였다.
3. 브라우저 기본 글꼴과 `wrap=off` 입력창 → 폐기. 글자 폭이 달라 긴 나레이션 단락에서 줄이 잘리고 줄바꿈이 어긋났다.

## 최종 방식

- **렌더가 현재 편집을 이미 반영한 상태**: 미리보기 렌더 이미지를 그대로 보여 준다. 입력창은 같은 자리, 같은 글꼴, 같은 줄로 겹쳐 두고 글자는 투명하게 해서 커서와 선택만 보인다.
- **입력 직후 렌더가 따라오기 전(pending)**: 그 영역만 마스크 배경(`restore_preview_url`, 없으면 `masked_url`, 둘 다 없으면 흰색)으로 덮고, 같은 폰트 파일로 렌더와 같은 위치에 글자를 그린다. 렌더 시점의 수동값과 현재 수동값을 비교해 pending을 판단한다.
- **초기 내용**: 직접 고친 글(`text_override`)이 없으면 입력창 내용은 렌더의 `text_layout` 줄 그대로다. 열기만 해서는 아무것도 저장되지 않는다.
- **렌더가 실제로 그린 위치를 기록**: `pipeline/render_text_overlay.py`의 `draw_text_block_pil`에 출력 전용 인자 `draw_record`를 추가해 줄별 x·y·폭, 줄 간격, ascent·descent, 자간, 외곽선 두께, 정렬을 `*_overlay_layout.json`의 각 영역 `draw`에 저장한다. 레이아웃 결정 로직은 건드리지 않았다. 레이아웃 파일 쓰기를 그리기 루프 뒤로 옮겼다.
- **폰트**: `/api/fonts`가 스타일별 실제 폰트 파일 이름(`styles`)을 돌려주고, 프런트가 FontFace로 불러 쓴다. 파일은 기존 `/fonts/<이름>` 경로를 쓴다.
- **세로쓰기**: 이 렌더러는 글자마다 한 줄로 위에서 아래로 쌓는다. 입력창도 CSS 세로쓰기를 쓰지 않고 그 줄을 그대로 따른다.

## 검증한 것

- 00004 R3(짧은 3줄 말풍선): 줄 폭 84/178/126px가 렌더 기록과 같다. 진입 전후 화면이 같다.
- 00092 R2(긴 5줄 텍스트 기반 단락): 줄바꿈 위치가 렌더와 같고, 줄 폭이 1px 안쪽 차이다. 박스 밖으로 나간 글자도 잘리지 않는다.
- Bold 전환, 좌 정렬, 크기 −, 타이핑 실시간 반영, 닫기 동작.

## 남은 한계

- pending에서 렌더 반영으로 넘어가는 순간 1px 안쪽 차이가 날 수 있다. 세로쓰기의 말줄임 점처럼 렌더러가 따로 그리는 글리프는 차이가 더 날 수 있다.
- 회전된 박스는 편집 글자가 회전을 따라가지 않는다.
- `Fonts/` 밖의 사용자 지정 폰트는 브라우저에서 불러오지 못해 기본 글꼴로 그린다.
- 예전에 만든 레이아웃 파일에는 `draw` 기록이 없다. 그런 페이지는 진입 직후 화면은 렌더 그대로지만 커서와 입력 중 글자 위치는 근사값이다. 한 번 다시 렌더하면 정확해진다.
- 직접 고친 여러 줄 글에서는 '세로' 버튼이 화면에 변화를 주지 않는다. 렌더러가 명시적 줄바꿈을 우선하기 때문이다.
- 같은 박스 재클릭 닫기는 글자 위를 누르면 커서가 놓이고, 글자 없는 곳을 눌러야 닫힌다.
- 확인하지 못함: 글꼴 스타일 버튼 전체, 글자색 스포이드, 마스크 이미지가 없는 페이지.

## 같은 날 함께 바뀐 것

- 글자색과 외곽선색을 박스별로 지정(`font_color`, `stroke_color`). 렌더는 `overlay_override_font_color`와 `overlay_override_stroke_color`를 쓴다. 색 프리셋은 검정, 흰색, 스포이드다.
- 스타일 버튼을 3×3 그리드로 줄이고 숫자 단축키 표시를 넣었다.
- 대사 리스트의 **확인/질문**은 혼자 쓰는 검수 표시다. 확인은 읽고 검수했다는 표시, 질문은 나중에 다시 볼 대사 표시다. 진행률, 완료 표시, 내보내기와 연결돼 있지 않고 브라우저 localStorage에만 저장된다. 안 써도 작업에는 영향이 없어 그대로 유지한다(`docs/editor_manual.html`에도 적어 두었다).

## 작업 중 발생한 데이터 변경

서브에이전트가 검증하며 00092 페이지(구형 키 페이지)에 Apply Overlay를 눌렀다. 가이던스 파일은 원래대로 되돌렸지만 `00092_final.jpg`와 `00092_overlay_layout.json`은 최신 코드로 다시 렌더됐고, 영역 5가 5:1·5:2로 나뉘어 대사 수가 6에서 8이 됐다. 원래 final은 백업이 없다.

## 2026-11-05 변경: 클릭은 확대, 편집은 더블클릭

- **한 번 클릭:** 박스로 확대하고 툴바(크기, 정렬, 쓰기 방향, 글꼴 스타일, 글자색, 외곽선)만 연다. 글 입력창은 열지 않는다. 툴바를 쓰려고 편집 모드에서 빠져나올 필요가 없게 하려는 것이다.
- **더블클릭·Enter:** 글 편집(제자리 입력창)을 켠다. 이때만 마스크 덮개와 입력창, 커서를 그린다.
- **Esc:** 편집 중이면 편집만 끝내고 확대·툴바는 유지한다. 한 번 더 누르면 확대를 닫고 전체 보기로 돌아간다.
- **다른 박스 클릭:** 닫지 않고 그 박스로 확대를 옮긴다.
- **‘클릭 시 박스 확대’ 체크(캔버스 왼쪽 아래, 기본 켬):** 끄면 클릭은 선택만 한다(툴바 없음, 오른쪽 패널로 지정). 브라우저에 저장한다(`comic-translator-overlay-focus-on-click`).
- **외곽선 기본 두께 1:** 렌더러 기본값(`TEXT_STROKE_WIDTH`, `DARK_TEXT_STROKE_WIDTH`)을 1로 낮췄다. 2 이상이면 이웃 글자의 외곽선이 붙어 겹쳐 보였다. 박스별로는 지금처럼 바꿀 수 있다.
- **외곽선 두께와 자간 연동:** 두께가 1을 넘으면 자간을 `(두께 - 1)px` 넓힌다(`set_stroke_tracking`). 레이아웃 계산(prepare)과 그리기 양쪽에서 박스마다 같은 값을 쓰고, 두께 1이면 보정이 0이라 기존 렌더와 같다. 편집 화면은 렌더가 기록한 자간(`draw.tracking`)을 그대로 쓴다. 세로쓰기의 글자 사이 간격은 이번에 건드리지 않았다.
- 예전에 렌더한 페이지의 기록에는 이전 두께(2)가 남아 있으니 Apply Overlay로 다시 렌더해야 새 기본값이 적용된다.
