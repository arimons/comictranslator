# Font Style TODO

OCR 프롬프트는 `font_style`을 제한된 enum으로 반환한다. 아직 실제 폰트 매핑은 임시이며, 아래 카테고리별 한국어 지원 폰트를 찾아야 한다.

## Font Style Categories

- `default`
  - 일반 인쇄체 또는 판단 불가.
  - 현재 기본 폰트 유지.

- `handwritten_round`
  - 둥글고 귀여운 손글씨.
  - 코미디, 당황, 귀여운 독백, 말랑한 감정 표현용 폰트 필요.

- `handwritten_rough`
  - 거칠고 불규칙한 손글씨.
  - 분노, 초조함, 절규, 거친 외침용 폰트 필요.

- `impact_bold`
  - 굵고 강한 강조체.
  - 위압감, 강한 대사, 큰 외침용 블랙/헤비 고딕 계열 폰트 필요.

- `serif_drama`
  - 명조/세리프 또는 날카로운 장식 획이 있는 극적 강조체.
  - 공포, 비극, 운명, 선언, 심각한 독백용 폰트 필요.
  - 00003 TG9 같은 케이스의 1차 후보.

- `sfx_brush`
  - 붓글씨 또는 효과음 전용 스타일.
  - 효과음, 타격음, 움직임 표현용 폰트 필요.

## Implementation Notes

- 현재 `pipeline/render_text_overlay.py`는 `font_style`을 읽지만, 실제 매핑은 임시로 `Pretendard-Black` 또는 `NanumBarunpenB`에 연결한다.
- 폰트를 추가하면 `font_path_for_cluster()`에서 enum별 경로를 명시적으로 매핑한다.
- `location == "unboxed"`이고 `font_type == "handwritten"`이면 원본 유지 정책을 우선한다.
- `location == "bubble"`이면 `handwritten`이어도 overlay 한다.

## 효과음 처리 흐름과 시점 (2026-11-12 협의)

효과음은 CV가 못 잡고(글자 묶음이 없어 영역이 안 만들어짐), 일반 대사처럼 번역·폰트 오버레이만으로 처리하기 어렵다. 그래서 **자동 분석에 넣지 않고, 사용자가 이 쪽은 효과음 번역이 필요하다고 판단할 때 요청**해서 쓴다.

1. **영역 분석 탭 `⋯` → `효과음 찾기`**: 비전 모델이 효과음의 읽기(예: グッ)와 대략의 박스를 주고, 텍스트 기반 영역(R)으로 추가한다. 박스가 작으면 영역 크기 조절로 맞춘다(`POST /api/sfx/locate`).
2. **지우기**: 그 영역의 지우기 줄에서 `AI`(영역 모드)를 고르면 효과음만 지운다. 이미지 모델이 지우는 것은 점 톤 배경에서도 잘 되는 것을 확인했다. 모델이 새 한글 효과음을 직접 그리게 하는 방식은 글자가 한글로 읽히지 않아 접었다.
3. **글자 입히기**: 그 영역의 번역문(효과음 한국어)을 개인 소장 붓체 폰트로 오버레이한다. 합성 시험에서 114(a꽃가람)·135(양재난초체M)·152(a행서체)와, 큰 충격음용 45(a태백산맥)를 후보로 골랐다. 폰트 파일은 저장소에 넣지 않고 맥미니가 읽는 별도 폴더에 둔다.

**아직 협의가 안 된 것**: 효과음을 언제 처리할지(쪽마다 수동 요청이 기본, 효과음이 많은 쪽에서 `AI로 쪽 전체 지우기`와 묶어 한 번에 처리할지), 효과음 위치를 찾으면서 바로 지우고 오버레이용 텍스트 박스까지 만드는 한 번의 동작으로 합칠지.

**만들어야 하는 것**: 오버레이의 기울임(전단) 값(효과음마다 사용자 지정, 처음 0도), 개인 폰트 폴더 읽기, 효과음 영역의 번역 문구 입력(영역 번역문 칸 재사용 검토).
