# 단일 페이지 미리보기와 서버 상태

2026-10-20

## 가로 이미지 나누기

가로로 두 쪽이 붙은 스캔(펼침면)을 같은 프로젝트 안에서 오른쪽 → 왼쪽 두 쪽으로 나눈다. 별도 프로젝트를 만들지 않는다.

- 시작 화면에서 이미지를 불러오면 가로 이미지가 있을 때 **"가로 이미지 N장을 두 쪽으로 나누기"** 선택이 보인다(기본 켜짐, 브라우저에 기억). 켜져 있으면 **분석 시작 직전**에 나눈다. 선택은 분석을 시작하기 전까지 바꿀 수 있다.
- 이미 편집기로 들어간 프로젝트는 최근 프로젝트 카드 메뉴의 **준비 화면에서 열기**로 홈 준비 화면(이미지 확인·제외, 가로 이미지 나누기)에 다시 불러온다. 홈에서 서버를 재시작하면 편집기가 아니라 이 준비 화면으로 돌아온다.
- 그 항목 안의 **미리보기·페이지별 조정** 링크가 미리보기 창을 연다(2026-10-28, 이전에는 왼쪽의 별도 버튼). 원본과 자르는 위치, 나뉜 조각을 보여 주며 분석·번역·복원 API를 실행하지 않는다. 창의 **이 프로젝트에 적용**으로 바로 나눌 수도 있다.
- 미리보기 창에서 가로 이미지마다 **자동 / 분할선 직접 지정 / 가로 그대로**를 고른다. 분할선은 원본 이미지에서 끌거나 클릭해 옮긴다. 고른 값은 `POST /api/pages/override`로 즉시 원본 페이지 기록의 `split_override`(`{"mode":"keep"}` 또는 `{"mode":"split","split_x":x}`, 자동이면 키 없음)에 저장되고, `page_plan`이 자동 판정 대신 이 값을 따른다. 그래서 분석 시작 때 자동 나누기에도 그대로 적용된다. 홈의 장수 문구는 '가로 그대로' 페이지를 빼고 센다.
- 편집기 상단에는 이 버튼을 두지 않는다(분석 전에 한 번 쓰는 준비 단계라서).

나누는 기준은 다음과 같다.

- 가로/세로 비율 1.25 이상을 가로 입력 후보로 본다.
- 좌우 각각 15% 이상의 넓은 밝은 여백 사이에 세로 콘텐츠가 있으면 **가운데만 한 장으로 남긴다.** 표지처럼 한 쪽짜리 그림이 가로 캔버스 가운데 놓인 경우이고, 이것이 자동 판정이라 작품마다 따로 알려 줄 필요가 없다. 표지 자체를 반으로 자르지 않는다.
- 다른 가로 입력은 이미지 폭 중앙에서 오른쪽 → 왼쪽 두 쪽으로 나눈다. 홀수 폭도 빠지는 열이 없다.
- 세로 이미지와 뚜렷한 내용이 없는 이미지는 그대로 둔다. 중앙 분할이 모든 작품의 실제 제본 위치나 의도된 연출을 검출하는 것은 아니므로 미리보기에서 확인한다.

나뉜 조각을 분석할 때 분할 전 원본(`source_image_sha256`)의 CV 캐시가 있으면 Cloud Vision을 다시 부르지 않고 그 결과를 조각 범위(`crop_rect`)로 잘라 쓴다(`app.py`의 `hydrate_cv_cache`, `crop_parent_cv_rows`). 글자 상자는 중심이 조각 안에 있으면 그 조각 것으로 보고 조각 경계에서 자른다. 이미 TG가 만들어진 조각의 일반 분석은 기존 결과를 유지하고, ‘처음부터 다시 분석’은 조각 자신의 CV 캐시를 건너뛰되 원본 CV를 잘라 Step 2-3을 다시 만든다. 원본 CV가 없으면 기존처럼 조각마다 Cloud Vision을 실행한다.

기준은 `pipeline/page_preparation.py`의 `page_plan`에 있다. 중앙 영역 추정에는 밝기 235 미만 픽셀이 세로 방향으로 4% 이상 존재하는 열을 사용한다. 옅은 워터마크·압축 잡음을 경계로 삼는 영향을 줄이기 위한 휴리스틱이며 내용의 의미를 판정하지 않는다. 중앙 crop에는 소량의 안전 여백을 더한다.

**저장 방식.** 나눈 조각만 PNG로 프로젝트의 `input/`에 저장하고(재압축 손실 방지), 원본 파일은 그대로 둔다. 원래 페이지 기록은 프로젝트 목록에서 조각으로 바뀐다. 이름은 `{원본이름}_p01_R.png`(오른쪽), `_p02_L.png`(왼쪽), `_p01_C.png`(가운데 한 장) 꼴이라 이름 정렬만으로 원래 페이지 순서와 읽기 순서(오른쪽 먼저)가 유지된다. 세로 이미지는 이름과 파일이 바뀌지 않는다.

각 조각에는 `parent_id`, `parent_name`, `parent_input_path`, `source_image_sha256`, `crop_rect`, `page_side`, `reading_order`, `split_policy`를 기록한다. crop은 원본 픽셀의 `[x,y,w,h]`이며 이후 분석 좌표는 조각 기준이다. 이미 나눈 조각은 다시 나누지 않아 여러 번 눌러도 안전하다. 같은 이름의 파일이 이미 있으면 아무것도 바꾸지 않고(저장한 조각도 지운다) 409로 알린다.

**작업 흔적이 있는 페이지.** 가이드 편집·번역 결과가 있거나 처리 제외한 페이지는 기본으로 건너뛴다. 자동 분석 결과만 있는 페이지는 작업 흔적으로 보지 않고 나눈다(2026-10-29, 조각은 원본 CV를 잘라 다시 분석하므로 잃는 것이 없다). 나누면 그 작업은 원래 페이지에 남고 조각에는 이어지지 않기 때문이다. 미리보기 창의 체크로 "작업 흔적이 있는 페이지도 나누기"를 고를 수 있다. 조각 이미지가 이전과 같은 바이트면 해시 키 분석 캐시는 그대로 재사용된다.

API:

- `POST /api/pages/preview`: `session_id` → 읽기 전용 계획(페이지별 `mode`, 조각 좌표·이름, 작업 흔적 여부 `has_work`)과 source URL. 이미 나눈 조각은 제외한다.
- `POST /api/pages/override`: `session_id`, `image_id`, `mode`(`auto`/`keep`/`split`), `split_x`(split일 때 필수) → 저장 후 그 페이지의 계획 하나(`page`)를 돌려준다. 이미 나눈 조각은 404.
- `POST /api/pages/split`: `session_id`, `include_worked`(기본 false) → 프로젝트에 적용하고 `split_pages`, `created`, `center_kept`, `skipped_worked`, 갱신된 `images`를 돌려준다. 나눌 이미지가 없으면 0을 돌려준다.
- 별도 프로젝트를 만들던 `POST /api/pages/prepare`는 없앴다. 이전에 만든 파생 프로젝트(`parent_session_id`)는 그대로 열린다.

직접 미리보기 링크는 `/?page_preview=SESSION_ID#home`이다. 홈으로 열며 프로젝트를 편집 상태로 불러오지 않는다. 미리보기를 닫으면 query를 제거한다.

프로젝트명 옆 작품 메모 버튼에서 작품 메모를 확인한다([작품 메모](WORK_GLOSSARY.md)). 앞쪽 페이지 CV에 메모의 원문 표기가 충분히 보이면 자동 연결한다. 잘못 연결되면 메모 창의 ‘변경’에서 바꾸거나 작품 없이 진행한다. 나누기 API 자체는 작품 메모를 만들거나 OpenAI·Gemini를 호출하지 않는다.

Ore_3(사망플래그 3권)는 83장 → 165장이다. `001.jpeg`는 가운데 768×1080 한 장, 나머지 82장은 각각 오른쪽/왼쪽 두 장이다(이전 방식으로 별도 프로젝트에 만들어 확인했고 원본 프로젝트의 1,340개 파일 크기·변경 시각과 manifest hash가 전후로 같았다).

## 서버 상태등

작업 중 팝업은 제거했다. 제목과 프로젝트명 사이의 상태등은 `GET /api/health`에 5초마다 연결한다. 브라우저 탭이 숨겨지면 새 확인을 멈추고 다시 보일 때 확인한다. 클릭하면 즉시 재확인할 수 있다.

- 초록: 정상 응답. 밝기가 천천히 변하는 효과를 사용하며 OS의 움직임 줄이기를 따른다.
- 노랑: 초기 확인 중, 1.2초 이상 응답 지연, 또는 첫 연결 실패.
- 빨강: 3초 제한 내 응답을 받지 못하거나 오류 응답을 연속 2번 받음. 이후 정상 응답 시 초록으로 복귀.
- 주황 "서버 재시작 필요": 서버가 불러온 프로젝트 Python 파일이 서버 시작 뒤 바뀌었다. `/api/health`의 `stale_code`가 바뀐 파일 목록이며 툴팁에 표시한다. 클릭하면 확인 후 `POST /api/server/restart`로 서버가 같은 명령으로 자기 프로세스를 다시 띄운다(`os.execv`, PID·포트 유지). 처리 중인 `/api` 요청(스트리밍은 끝날 때까지)이나 백그라운드 재적용이 있으면 409로 한 번 더 확인받고, 강제로 재시작하면 그 작업은 중단된다. 재시작이 끝나면 화면을 새로고침하고, 편집기에서는 보던 프로젝트·페이지·탭을 다시 연다(sessionStorage에 한 번만 기억).
- 파랑 "새로고침": 화면 번들(`web/app.bundle.js`)이 이 화면을 연 뒤 다시 빌드됐다(`/api/health`의 `bundle`). 클릭하면 새로고침한다.

우선순위는 빨강 > 주황 > 파랑 > 노랑·초록이다. 이 등은 서버 연결과 코드 버전만 표시한다. 분석·OCR·번역 성공 여부나 worker 상태를 보장하지 않는다. 실제 작업 로그와 이미지별 상태는 해당 편집기 탭에서 확인한다.

## 이미지 보기

영역 분석 탭의 "마스크" 비교 이미지는 확정한 배경 복원 패치(AI 글자 지우기 포함)가 있으면 그것을 얹은 `restore_preview_url`을, 없으면 `masked_url`을 보여 준다. AI 글자 지우기 후보는 별도 "AI 지움 후보" 탭에 뜬다.

비교 이미지에는 전체 맞춤·너비 맞춤·확대·축소를 제공하며 작은 원본도 보기 영역까지 확대한다. 캔버스가 맞춤 모드일 때 창/패널 크기가 바뀌면 배율을 다시 계산한다. 사용자가 직접 확대한 상태는 유지한다. 영역 분석 캔버스는 맞춤 시 이미지를 도구 모음 옆(70px)에 왼쪽 정렬하고, 이미지가 15% 넘게 작아지지 않으면 오른쪽에 선택 정보 패널 폭(324px)을 비운다.

검증: `tests/test_page_preparation.py`는 crop 순서·원본 보존·오래된 revision 거절·새 프로젝트 분리·health 읽기 전용을 검사한다. `proof/src/check_page_preparation.js`는 실제 Ore_3 미리보기, 상태등 전환, 모바일 넘침, 실제 생성·분석 요청 0회를 확인한다. `proof/src/test_viewport_fit.mjs`는 창 크기 변경 시 맞춤 재계산과 수동 확대 유지, 왼쪽 정렬과 패널 자리 비우기를 검사한다.

완료 시점 검증: 전체 pytest 478개 및 13개 subtest 통과. 프론트엔드 빌드와 뷰포트 검증도 통과했다.

- 새 프로젝트의 분석 JSON·최종 출력은 없다. CV/OCR/번역/이미지 생성은 실행하지 않았다.
- 생성 절차와 검증은 `proof/src/create_ore3_single_page_project.py`에 보존했다. 같은 이름·부모 세션·분할 revision이 일치하면 기존 프로젝트를 재사용해 중복 생성을 피한다.

2026-10-20 후속: 새 프로젝트의 커버 1장은 내장 이미지 생성 결과를 미검토 후보로 등록했다. 분할 원본·기존 프로젝트는 유지되며 최종 출력은 비어 있다. [이미지 생성 연결](IMAGE_GENERATION_REVIEW.md)에 별도로 기록한다. 생성 후보 검토 링크는 자동 분석을 실행하지 않는다.

OpenAI 전환(2026-10-20): OCR·번역 및 URL 자료의 용어 정리는 OpenAI를 사용한다. 페이지 정리 API는 여전히 분석·번역·용어 정리를 자동 호출하지 않는다.

분할 후 수동으로 모든 TG를 제외한 페이지는 분석 완료·Region 0개 상태다. 미분석 페이지와 구분하며 원본을 유지한다. 자동 Region 제외는 텍스트 기반 fallback에도 적용된다.

분할된 입력도 페이지별로 전체 처리에서 제외·복원할 수 있다. 제외한 경우 분할된 input 파일이 그 페이지의 원본 출력이며, 분할 전 부모 이미지를 대신 출력하지 않는다. 페이지 복원은 기존 TG 개별 제외를 취소하지 않는다.


2026-10-20 UI 동기화: 단일 페이지 프로젝트의 표지 생성 후보는 해당 페이지의 비교 미리보기에서 확인한다. 기존 CV·영역 분석 방식으로 전환하는 설정은 페이지 로컬 analysis_route로 저장하며, 부모 프로젝트·분할 원본·생성 후보를 변경하지 않는다. 미리보기 실패는 재시도 버튼을 제공한다.

편집기에서 TG와 R은 독립 선택한다. 단일 페이지의 화자도 해당 페이지 R에 저장하며 TG가 없는 수동 영역에 지정할 수 있다. 부모/다른 페이지의 화자 기록을 변경하지 않는다.
