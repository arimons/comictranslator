## 항목별 원인과 변경

### 1. 없는 프로젝트를 열면 빈 프로젝트가 생김

조회 경로도 `ensure_session()`을 불렀고, 이 함수가 폴더와 `project.json`을 만들었기 때문입니다. 브라우저가 기억한 프로젝트가 지워졌거나 다른 기기에 있으면 "Untitled project 0/0" 편집기로 들어가고 빈 폴더가 남았습니다.

`app.py`에 `load_session()`을 두어 프로젝트가 없으면 404를 주고 아무것도 만들지 않게 했습니다. 예전 `session.json` 프로젝트도 그대로 읽습니다. 만드는 경로는 새로 만들기(`POST /api/sessions/new`), 업로드, 서버 폴더 가져오기 세 곳만 남겼고, 나머지 조회·수정과 분석·번역 스트림은 `load_session()`을 씁니다(스트림은 오류 이벤트로 알립니다). 화면은 기억해 둔 프로젝트가 404이면 기억을 지우고 "프로젝트를 찾을 수 없어 홈으로 돌아왔습니다" 안내와 함께 홈으로 갑니다. `tests/test_missing_session.py`(12개)가 없는 id의 404와 폴더 미생성, 만드는 경로와 구 manifest 유지를 확인합니다.

### 2. 프로젝트를 바꾸면 이전 페이지 ID로 요청이 나감

세션 id만 바뀌고 이미지 목록과 선택 페이지는 응답이 올 때까지 이전 프로젝트 것으로 남아, 새 세션 id와 이전 페이지 id 조합으로 페이지 상세·화자 요청이 나가 404가 났습니다. 프로젝트를 바꾸는 순간(`setSessionTracked`) 목록과 선택을 같은 render에서 비우도록 했습니다. 브라우저에서 A→B, B→A 전환 모두 404가 0건임을 확인했습니다.

### 3. 1280px 아래에서 편집기가 무너짐

편집기 이전의 3단 레이아웃용 1180px 규칙이 오른쪽 패널(글자 입히기 스타일·대사, 내보내기 설정)을 숨기고 비교 미리보기를 세로로 쌓은 것이 원인이었습니다. 그 규칙을 편집기에서 빼고, 보조 창(영역 분석 비교 미리보기, 글자 입히기 원본)은 옆에 좁게 두되 머리줄 토글("◂ 비교"는 1279px 이하, "◂ 원본"은 1400px 이하)로 접게 했습니다. 접은 상태는 브라우저에 기억됩니다. 내보내기·글자인식 머리줄은 좁으면 줄바꿈하고, 글자 입히기 캔버스는 창 크기뿐 아니라 칸 크기가 바뀌어도 다시 맞춥니다(`ResizeObserver`). 1440px 이상 레이아웃은 바꾸지 않았습니다.

| 창 크기 | 영역 분석 캔버스 | 글자 입히기 캔버스 | 잘린 버튼 | 가로 스크롤 |
|---|---|---|---|---|
| 1440×900 | 812×742 | 569×742 | 0 | 없음 |
| 1280×800 | 720×606 | 437×606 | 0 | 없음 |
| 1100×720 | 780×526 | 352×526 | 0 | 없음 |
| 960×700 | 677×506 | 298×506 | 0 | 없음 |

네 탭 모두, 새로고침 없이 크기만 바꿨을 때도 같은 값이고 이미지가 캔버스 안에 들어갑니다. 수정 전 1100px에서는 비교 미리보기가 2% 썸네일, 캔버스가 높이 346px로 줄었고 글자 입히기 오른쪽 패널과 내보내기 ZIP 버튼이 사라졌습니다. 수정 전 상태는 1440px과 1100px에서만 기록했습니다.

### 4. 글자 입히기에서 대사 리스트 자리가 없음

오른쪽 패널을 세로 배치로 바꿔 대사 리스트가 패널 높이의 절반 이상을 쓰고 안에서 스크롤하게 했습니다. Selected Style은 머리줄을 눌러 접을 수 있고, 접어도 현재 스타일 이름이 보이며 숫자 키 1〜9는 그대로 선택 영역에 적용됩니다. 1440×900에서 다 보이는 대사 행은 1개에서 펼침 2〜3개, 접음 3〜4개가 됐습니다. J/K, Y, Q, 숫자 키, ⌘Enter가 동작함을 브라우저에서 확인했습니다.

### 5. 프로젝트 등록과 동시에 분석 시작

업로드나 서버 폴더 가져오기로 새 프로젝트가 생기면, 홈 준비 화면에서 1쪽부터 분석합니다. "다음 페이지 미리 분석"이 켜져 있으면 1〜6쪽, 꺼져 있으면 1쪽만입니다. 기존 미리 분석과 같은 한 장 잠금(`prefetchPromiseRef`)을 써서 `/api/analyze-stream`이 동시에 둘 나가지 않고, 편집기에 들어가면 보고 있는 페이지가 먼저입니다. 처리 제외·생성 권장 페이지와 나누기 전 가로 이미지는 건너뛰고, 업로드 캐시 연결이 끝난 뒤 시작합니다. 기존 프로젝트를 열 때는 시작하지 않습니다. 준비 화면 시작 버튼 위에 "3쪽 분석 중 · 미리 분석 4/6" 같은 진행과 Cloud Vision 사용 안내가 보입니다. 판정은 `frontend/src/prefetchPlan.js`의 순수 함수(`earlyAnalysisWindow`, `pickEarlyAnalysisTarget`, `earlyAnalysisProgress`)에 두고 `proof/src/test_prefetch_plan.mjs`에서 검사합니다.

새 프로젝트 요청 순서는 다음과 같이 확인했습니다.

| 경우 | 홈에서 나간 요청 | 편집기 진입 뒤 |
|---|---|---|
| 캐시된 예시 6쪽(4쪽은 이미 분석됨) | 00008(1.8〜8.0초) → 00011(8.0〜14.1초), 겹침 없음, `force=false` | 5초간 0건, 1쪽 바로 표시 |
| 빈 페이지 7장, 키 없음(모두 실패) | p01〜p06 각 1회, 순서대로 | 1쪽만 1회 재시도 |
| 미리 분석 설정 꺼짐 | p01 1건 | — |
| 처음부터 다시 분석 선택 | 진행 중이던 1건만, 이후 0건 | 시작 시 전체 강제 재분석 |

## 보수적으로 정한 것과 다른 선택지

- **처음부터 다시 분석과의 관계.** 미리 분석은 "기존 결과 활용"(`force=false`)으로 시작합니다. 준비 화면에서 "처음부터 다시 분석"을 고르면 새 요청을 보내지 않고 진행 중인 한 장만 마치며, 시작 버튼을 누를 때 전체를 강제로 다시 분석합니다. 그 전에 끝난 페이지는 두 번 분석될 수 있습니다. 진행 중 요청을 중단하는 방법은 서버가 중단을 받지 않아 쓰지 않았습니다.
- **가로 펼침 후보는 미리 분석하지 않습니다.** 시작할 때 나누면 분석이 헛돌기 때문입니다. 나누기 결정이 끝난 뒤 미리 분석하도록 바꿀 수는 있습니다.
- **가로 나누기와 프로젝트 삭제는 진행 중인 한 장이 끝날 때까지 기다립니다.** 프로젝트 파일을 동시에 고치거나, 지운 폴더에 분석 결과가 다시 쓰이지 않게 하려는 것입니다. 기다리는 동안 상태줄에 안내가 나옵니다.
- **보조 창은 기본으로 펼쳐 둡니다.** 좁은 창에서 기본으로 접는 선택지도 있지만, 처음 보는 사람이 원본·비교 창이 사라졌다고 느끼지 않게 했습니다.
- **스타일 설정도 기본으로 펼쳐 둡니다.** 펼쳐도 대사 리스트가 절반 이상을 가지므로 기본을 바꾸지 않았습니다.

## 삭제 시나리오 검증

방금 만든 프로젝트를 미리 분석 도중에 지우는 경우를, 한 장에 약 6초가 걸리도록 Cloud Vision 캐시만 둔 예시 이미지로 확인했습니다. 처음 확인에서는 삭제 버튼이 진행 중인 한 장을 기다리는 사이 그 한 장이 끝나자 미리 분석이 다음 쪽 요청 3건을 이어 보냈고, 그중 1건은 삭제 뒤에 나갔습니다. 폴더가 되살아나지는 않았지만 요청이 남는 문제라 `d7c8b9f`에서 삭제를 누르면 미리 분석부터 끄도록 고쳤습니다.

| 경우 | 분석 요청 | 삭제 뒤 요청 | 15초 뒤 폴더 |
|---|---|---|---|
| 첫 요청 직후 화면에서 삭제(수정 후) | 1건(진행 중이던 1쪽) | 0건 | 없음 |
| 3쪽 진행 중 화면에서 삭제(수정 후) | 3건 | 0건 | 없음 |
| 화면 밖에서 API로 삭제 | 남은 쪽당 1회씩 6건, 곧바로 실패 후 멈춤 | 이후 40초간 0건 | 끝까지 없음 |

화면에서 지우면 상태줄에 "진행 중인 미리 분석 한 장이 끝나면 삭제합니다…"가 나오고, 끝나면 홈 목록과 준비 화면이 비워집니다. 새로 만든 프로젝트 카드는 최근 목록을 다시 불러와야(정렬 변경 등) 나타나므로, 실제 사용에서 이 경로를 밟는 일은 드뭅니다.

## 남은 것

- **이번 범위 밖에서 본 기존 동작.** 새로 만든 프로젝트 카드가 홈 최근 목록에 바로 나타나지 않습니다(목록을 다시 불러와야 보임). 최근 목록은 같은 이미지 묶음을 가진 프로젝트를 하나로 묶어 다른 카드를 가릴 수 있습니다. 미리 분석 중 ··· 메뉴가 목록 재렌더로 저절로 닫힌 적이 있습니다.
- 백로그 6절의 라벨 언어·버튼 무게·일관성 항목은 이번 범위가 아니어서 손대지 않았습니다.

## 검증 방법

전체 검사는 `python -m pytest -q`(770 통과, 폰트 3개 건너뜀), `ruff check .`, `cd frontend && npm test`(13 통과)입니다. 브라우저 확인은 사용자 데이터 홈을 쓰지 않고, 비운 API 키와 임시 데이터 홈(`COMIC_TRANSLATOR_HOME`)으로 띄운 서버에서 했습니다. 매뉴얼 예시 프로젝트 사본(분석 완료)과 빈 PNG, 그리고 Cloud Vision 캐시만 옮긴 예시 이미지를 써서 유료 호출 없이 실패 경로와 성공 경로를 모두 봤습니다. 브라우저 조작 검증은 Sonnet 서브에이전트가 맡았습니다.
