# 원본 직접 참조와 기기별 재연결

2026-10-21. 일반 페이지를 입력 캐시에 복제하는 기본 동작을 원본 직접 참조로 변경했다.
페이지 ID·파일 별칭·CV·분석 캐시·R/TG·화자·수동 편집·생성 후보·최종 출력 경로는 유지한다.

## 저장 계약

| 종류 | 저장 방식 |
|---|---|
| 서버의 폴더 경로로 불러온 일반 페이지 | 지정한 원본을 읽기 전용 참조. cache/input에 새로 복사하지 않음 |
| 분할·크롭 결과 | 프로젝트 input 안에 실제 파일 보관. 원본 재연결 대상에서 제외 |
| 브라우저 파일/폴더 선택·드롭 업로드 | 브라우저는 절대 경로를 전달하지 않으므로 프로젝트 input 안에 보관. 나중에 원본 폴더를 지정해 전환 가능 |
| 이전 cache/input 사본 | 호환·오프라인 대체 입력으로 유지. 자동 삭제하지 않음 |
| cache/cv, cache/analysis | 기존 이미지 해시 기반 재사용을 그대로 유지 |

웹 브라우저에서 원본 직접 참조를 사용하려면 홈의 **원본 폴더 경로로 불러오기**를 사용한다.
이 경로는 브라우저를 실행한 컴퓨터가 아니라 서버(맥 미니)에서 접근할 수 있는 경로다.
경로 입력란 옆 **찾아보기**(2026-10-28)는 `GET /api/fs/list`로 서버의 폴더를 둘러보는 창이다. 홈 폴더와 `/Volumes` 아래 외장 볼륨을 바로가기로 보여 주고, 고른 폴더를 같은 원본 직접 참조로 불러온다.

## 메타데이터와 별칭

project.json의 images 항목은 아래 필드를 추가로 사용한다. 기존 항목이 없어도 이전 방식으로 읽는다.

- input_storage: source / derived / upload / legacy_cache.
- source_ref.root_id: 원본 루트의 논리 ID.
- source_ref.relative_path: 해당 루트 아래 상대 파일 경로.
- image_sha256: 기존 콘텐츠 해시. 연결 전에 실제 파일과 비교한다.
- source_fallback_path: 이전 입력 사본이 있을 때 프로젝트 기준 상대 경로로 보존한다.

input_path는 프로젝트 안의 원래 별칭과 페이지 ID를 유지한다. 일반 페이지의 별칭은 심볼릭 링크다.
링크 자체를 유일한 근거로 삼지 않고 source_ref와 해시를 저장해 위치 변경 시 앱이 다시 만들 수 있게 했다.
분할·크롭 파일은 링크를 사용하지 않는다. 이 방식으로 기존 파이프라인과 산출물 파일명을 유지한다.

가로 이미지 나누기([PAGE_PREPARATION.md](PAGE_PREPARATION.md))도 같은 프로젝트 안에서 조각을 이 방식으로 프로젝트 input에 보관한다(2026-10-22부터 별도 프로젝트를 만들지 않는다). 나눈 원래 페이지의 원본 파일은 그대로 두고, 각 조각의 `parent_input_path`와 `source_image_sha256`이 그 원본을 가리킨다. 이미 나눈 조각은 원본 재연결 대상에서 계속 제외한다.

원본은 앱에서 덮어쓰거나 삭제하지 않는다. 페이지 제거는 프로젝트 별칭만 제거한다.
원본 내용이 바뀌면 기존 해시와 일치하지 않으므로 이전 사본으로 전환하거나 원본 없음으로 표시한다.
이 상태에서 예전 CV를 새 픽셀에 조용히 적용하지 않는다.

## 맥 미니에서 연결

1. 프로젝트를 연 뒤 상단의 **원본 연결**을 연다.
2. 맥 미니의 압축 해제된 원본 폴더 경로를 입력한다. 하위 폴더도 찾는다.
3. **원본 확인**을 누르면 파일명·해시를 비교한다. 파일명이 바뀌었어도 같은 해시의 파일을 찾는다.
4. 동일 파일·분할 보관·미일치 장수를 확인하고 **일치한 N장 연결**을 누른다.
5. 동일한 일반 페이지에만 적용한다. 미일치 페이지와 기존 결과는 유지하며 분할·크롭은 건드리지 않는다.

미리보기 뒤 파일/프로젝트가 바뀌면 적용을 거부하고 다시 확인하도록 한다.
기존 manifest와 링크 정보는 프로젝트 work/source_history에 보존한다.
재연결에 CV·번역·이미지 생성 API(OpenAI·Gemini 모두)를 호출하지 않는다.

실제 원본 경로는 데이터 홈 local/hosts/{호스트 식별 해시}/source_roots.json에 둔다.
호스트 식별은 macOS에서는 하드웨어 UUID(`stable_host_id`), 다른 OS에서는 호스트 이름을 쓴다. macOS 호스트 이름은 네트워크에 따라 바뀌어
(예: `…-MacBook-M3-Pro.local` → `Mac`) 원본 등록을 잃고, 원본 직접 참조 페이지의 서빙이 거부되거나 예비 경로가 없으면 입력 링크가
'원본 없음'으로 바뀌었기 때문이다. 새 ID의 등록이 없으면 이 기기의 여러 이름(`this_host_names`: 호스트 이름, LocalHostName,
LocalHostName.local, HostName, ComputerName)으로 저장된 예전 등록만 이어받고, 예전 파일은 남긴다. 다른 기기의 등록은 받지 않는다.
COMIC_TRANSLATOR_HOST_ID로 호스트 ID를 직접 지정할 수도 있다.
파일 서빙(`allowed_source`)은 등록된 원본뿐 아니라, 해시가 맞는 예비 경로(`source_fallback_path`)도 등록된 페이지로 인정한다.
동일한 폴더 구조를 다른 기기에 연결하면 논리 root_id를 유지하고 그 기기의 경로만 등록한다.
폴더 내부 구조·파일명이 바뀌면 source_ref도 갱신한다. 여러 기기에서 데이터 홈을 복제하더라도 동시에 편집하지 않고 서버 한 대를 실행 주체로 사용한다.

## 기존 프로젝트 이전

```sh
# 기본은 미리보기. 후보 원본은 데이터 홈 samples 아래에서 찾는다.
.venv/bin/python scripts/migrate_input_sources.py
# 다른 라이브러리를 사용할 때
.venv/bin/python scripts/migrate_input_sources.py --source-root /Volumes/Comics
# 편집기 서버를 종료한 뒤 실행
.venv/bin/python scripts/migrate_input_sources.py --source-root /Volumes/Comics --apply
```

현재 MacBook에서는 samples에 보존한 원본을 이용해 일반 969장을 직접 참조로 전환하고 분할·크롭 165장을 프로젝트 소유로 보존했다.
미일치 페이지는 없었다. 기존 입력 캐시를 삭제하지 않았고 CV·분석 캐시를 재생성하지 않았다.
맥 미니에 같은 samples를 옮길 필요는 없다. 맥 미니에 이미 있는 원본 폴더를 UI에서 다시 지정하면 된다.

## cache/input을 앞으로 유지할지

새 일반 페이지의 필수 저장소로 사용하지 않는다. 기존 프로젝트와 원본 미연결 상태를 위한 호환 사본으로 남긴다.
맥 미니에서 원본 연결을 확인할 때까지 유지하는 것이 좋다. 이전 보관 프로젝트도 사본을 참조하므로 일괄 삭제하지 않는다.
향후 정리할 때는 활성·보관 프로젝트 및 대체 입력 참조를 모두 조사한 뒤 미사용 파일만 별도 정리해야 한다.
CV·분석·LaMa 모델 캐시는 이 입력 사본과 별개다.

## MCP와 파일 제공

MCP는 UI 서버 없이 등록된 원본 또는 해시가 맞는 대체 사본을 읽는다. MCP 조회 자체가 별칭을 수정하지는 않는다.
외부 폴더 전체를 공개하지 않고 프로젝트에 등록된 해시 일치 원본 파일만 파일 API와 MCP의 읽기 대상으로 허용한다.
기존 세션·캐시 내부 경로 제한과 제안 저장 범위는 유지한다.
