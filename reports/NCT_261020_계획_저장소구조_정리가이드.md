# 저장소·작업 데이터 구조 정리 가이드

> 대상: 이 가이드를 받아 실제 정리를 수행할 에이전트(Codex)
> 작성: 2026-10-20 · 실행 환경 목표: 맥 미니(내장 SSD) + 만화 원본 zip이 든 외장하드

이 문서는 "무엇을 어디로 옮기고, 무엇을 고치고, 어떻게 확인하는지"를 순서대로 적은 작업 지시서입니다.
한 번에 다 하지 말고 **단계마다 테스트를 통과시키고 커밋**한 뒤 다음 단계로 갑니다.

---

## 1. 지금 무엇이 문제인가

- **코드와 작업 데이터가 한 폴더에 섞여 있다.** 저장소 루트 안에 작업 데이터가 약 20GB 있다.
  `temp_output/` 7.8GB, `proof/` 4.4GB, `archive/` 4.4GB, `output/` 2.7GB, `test_image1/` 978MB.
  모두 git에서 제외돼 있지만, 검색·백업·에이전트 탐색이 매번 이 데이터를 훑는다.
- **이름이 실제 의미와 다르다.** 프로젝트 데이터가 "임시"(`temp_output`)에 있고, 화면은 "프로젝트"라 부르는데
  폴더는 `v2_sessions`다. `main_v2.py`, `ui_v2/`, `v2_*_cache`처럼 버전 표시가 이름에 남아 있다.
- **경로가 여러 곳에 하드코딩돼 있다.** `main_v2.py`(`SESSION_ROOT` 등 5개 상수와 용어집 경로),
  `pipeline/editor_review_bridge.py`, `pipeline/image_generation_bridge.py`, `run_editor_mcp.py`, `run_pipeline.py`
  기본값, 테스트 여러 개, 문서 십여 개.
- **JSON에 절대 경로가 저장된다.** 예: `session.json`의 `images[].input_path`, `regions.json`의 `mask_ref`.
  입력 이미지는 전역 입력 캐시를 가리키는 링크다. 폴더만 옮기면 기존 프로젝트가 깨진다.

## 2. 저장 위치 설계 (SaaS 관점)

서비스로 운영한다고 생각하면 데이터는 성격에 따라 네 칸으로 나뉩니다. 로컬 앱도 같은 칸을 쓰면 나중에
서버로 옮기기 쉽고, 지금도 백업·정리 기준이 명확해집니다.

| 칸 | SaaS에서 | 이 앱에서 | 위치 | 성격 |
|---|---|---|---|---|
| 원본 라이브러리 | 원본 버킷(읽기 전용) | 만화 zip | **외장하드 그대로** | 앱이 절대 수정하지 않음. 복사해 오지 않음 |
| 프로젝트 데이터 | DB + 사용자 파일 | 프로젝트 메타, guidance, 영역, OCR·번역, 수동 보정, 확정 패치 | **내장 SSD** `~/ComicTranslator/projects/` | 사용자의 작업물. 백업 대상 |
| 캐시 | 캐시 계층 | 입력 페이지, CV 결과, 분석 결과 | **내장 SSD** `~/ComicTranslator/cache/` | 지워도 다시 만들 수 있음. 백업 제외 |
| 내보내기 | 다운로드 산출물 | 최종 이미지·zip | 기본 `~/ComicTranslator/exports/`, 사용자가 지정 가능(외장하드 원본 옆 등) | 결과물 |

**왜 프로젝트를 외장하드 원본 옆에 두지 않나**
- 외장하드는 느리고, 분리돼 있으면 프로젝트가 열리지 않는다.
- 원본 라이브러리에 앱이 만든 파일이 섞이면, 원본을 정리하거나 다른 프로그램으로 볼 때 방해가 된다.
- 내보내기 결과만 원본 옆에 두고 싶다면 내보내기 위치 설정으로 해결한다.

**왜 저장소 밖(`~/ComicTranslator`)인가**
- 코드를 다시 받거나 저장소를 지워도 작업물이 남는다.
- 에이전트와 검색이 코드만 본다.
- 위치는 환경변수 `COMIC_TRANSLATOR_HOME`으로 바꿀 수 있게 한다(테스트, 다른 디스크).

## 3. 목표 구조

> **저장소 폴더 이름은 바꾸지 않는다.** 코드는 지금 위치(`~/Developer/NEW_COMIC_TRANSLATOR`) 그대로 두고,
> 작업 데이터만 저장소 밖의 새 폴더(`~/ComicTranslator`)로 옮긴다. 두 폴더는 별개다.
> 저장소 폴더 이름을 바꾸면 `.venv`(절대 경로를 품고 있음)를 다시 만들어야 하고 에이전트 설정·메모리도 새로 시작되므로,
> 바꾸고 싶다면 맥 미니로 옮길 때 함께 한다.

### 3-1. 저장소(코드만)

```text
NEW_COMIC_TRANSLATOR/
├── app.py                  편집기 서버 실행 (← main_v2.py)
├── run_pipeline.py         CLI 실행 (그대로)
├── pipeline/               파이프라인 모듈 (그대로)
│   └── paths.py            ★ 새로 만든다: 데이터 위치의 유일한 정의
├── frontend/               React 소스 (그대로, 빌드 출력만 ../web)
├── web/                    빌드된 화면 자산 (← ui_v2/)
├── scripts/                보조 실행기 (← 루트의 run_debug_pipeline.py, visualize_debug.py,
│                           run_editor_mcp.py, configure_editor_mcp.py)
├── batch/ Fonts/ tests/ docs/ reports/
└── (git 제외) .env, .venv/, archive/, proof/
```

- `run_floodfill_batch.py`는 폐기 모듈을 import해 지금 실행되지 않는다. `archive/`로 옮긴다.
- `batch_history.log`, `learning-log.md`는 성격을 확인해 `docs/` 또는 `archive/`로 옮긴다.
- `test_image/`, `test_image1/`, `output/`은 코드가 아니다. 4장의 데이터 이전 대상이다.
- `proof/`는 `proof/src/`(git 관리 스크립트)만 저장소에 남기고, 출력물은 데이터 홈의 `legacy/proof_outputs/`로
  옮기는 것을 권한다. 단, 테스트나 문서가 `proof/` 출력물을 참조하면 먼저 확인한다.
- `archive/`(git 제외, 4.4GB)는 이번에는 옮기지 않는다. 별도 정리 과제로 남긴다.

### 3-2. 데이터 홈 (`COMIC_TRANSLATOR_HOME`, 기본 `~/ComicTranslator`)

```text
~/ComicTranslator/
├── config.json                  라이브러리 루트(외장하드 경로 목록), 기본 내보내기 위치
├── projects/{project_id}/        (← temp_output/v2_sessions/{session_id}/)
│   ├── project.json             (← session.json)
│   ├── input/  work/  output/   (내부 구조는 이번에는 그대로)
├── cache/
│   ├── input/                   (← temp_output/v2_input_cache/)
│   ├── cv/                      (← temp_output/v2_cv_cache/)
│   └── analysis/                (← temp_output/v2_analysis_cache/)
├── glossaries/                  (← temp_output/v2_glossaries/)
├── inbox/image_generation/      (← temp_output/image_generation_inbox/)
├── exports/
├── samples/                     (← test_image/, test_image1/)  테스트용 원본
└── legacy/                      지우지 않고 모아 두는 곳 (4-3 참고)
```

- `project_id`는 지금 세션 ID를 그대로 쓴다(예: `20261020_075649`). 새 ID 체계로 바꾸지 않는다.
- 코드 안의 변수명·함수명(`session_id`, `SESSION_ROOT` 등)과 API 경로(`/api/session/...`)는 **이번에는 바꾸지 않는다.**
  화면·폴더 이름만 맞춘다. 내부 이름까지 바꾸면 변경 폭이 너무 커진다.
- `project.json`은 읽을 때 `session.json`이 있으면 그것도 읽어 들인다(이전 직후 호환).

## 4. 작업 순서

### 0단계. 준비
1. 현재 작업을 모두 커밋한다. `git status`가 깨끗해야 한다.
2. 편집기 서버를 끈다.
3. 기준 테스트: `.venv/bin/python -m pytest -q` 결과(통과 개수)를 기록한다.

### 1단계. 경로 정의를 한 곳으로 (`pipeline/paths.py`)
- `COMIC_TRANSLATOR_HOME`(없으면 `~/ComicTranslator`)에서 아래 경로를 만든다.
  `PROJECTS_DIR`, `INPUT_CACHE_DIR`, `CV_CACHE_DIR`, `ANALYSIS_CACHE_DIR`, `GLOSSARY_DIR`,
  `IMAGE_GENERATION_INBOX`, `EXPORTS_DIR`, `LEGACY_DIR`.
- 저장소 경로(`REPO_ROOT`, `WEB_DIR`, `FONTS_DIR`)도 같은 모듈에 둔다.
- 아래 파일의 하드코딩을 모두 이 모듈로 바꾼다. **이 단계에서는 값이 아직 옛 위치를 가리켜도 된다**
  (예: 일시적으로 `COMIC_TRANSLATOR_HOME` 기본값을 옛 구조로 매핑). 목적은 참조를 한 곳으로 모으는 것.
  - `main_v2.py`: `UI_DIR`, `SESSION_ROOT`, `INPUT_CACHE_DIR`, `CV_CACHE_DIR`, `ANALYSIS_CACHE_DIR`, 용어집 경로,
    번들 경로(`ui_v2/app.bundle.js` stat)
  - `pipeline/editor_review_bridge.py`: 세션 루트와 허용 경로 목록
  - `pipeline/image_generation_bridge.py`: 용어집 경로, 생성 이미지 inbox 경로
  - `run_editor_mcp.py`: 도움말 문구 안의 inbox 경로
  - `run_pipeline.py`: `--work-dir` 기본값 `temp_output`
- 테스트가 `temp_output`·`v2_sessions` 문자열을 직접 쓰는 곳(`tests/test_editor_mcp.py`,
  `tests/test_image_generation_bridge.py`, `tests/test_work_glossary.py`, `tests/test_page_processing.py`,
  `tests/test_docs_sync.py`)은 `paths` 모듈이나 `tmp_path`를 쓰게 고친다.
- 확인: 전체 테스트 통과 개수가 0단계와 같다. 편집기를 띄워 기존 프로젝트 하나를 연다.
- 커밋.

### 2단계. 이름 변경 (코드)
| 이전 | 이후 |
|---|---|
| `main_v2.py` | `app.py` |
| `ui_v2/` | `web/` |
| `frontend/package.json`의 `--outfile=../ui_v2/app.bundle.js` | `--outfile=../web/app.bundle.js` |
| `.claude/launch.json`의 `main_v2.py` | `app.py` |
| 루트 보조 스크립트 | `scripts/` (위 3-1 목록) |

- `git mv`로 옮겨 이력을 남긴다.
- import 경로가 바뀌는 곳: `tests/` 안의 `import main_v2` / `from main_v2 import …` (12개 파일 정도),
  `scripts/`로 옮긴 파일이 `pipeline`을 import하는 방식(작업 디렉터리 기준이면 `sys.path` 처리 필요).
- 문서: `AGENTS.md`, `CLAUDE.md`, `README.md`, `docs/CODEBASE_FILE_MAP.md`, `docs/pipeline_guide.html`,
  `docs/DOC_SOURCES.json`(sources 목록), 그 밖에 `main_v2`·`ui_v2`를 언급하는 문서.
  `tests/test_docs_sync.py`가 없는 파일을 가리키는 문서를 잡아 주므로 그 결과를 따라 고친다.
- 확인: 전체 테스트 통과, `cd frontend && npm run build`가 `web/app.bundle.js`를 만든다, `python app.py --no-browser`로
  화면이 뜬다.
- 커밋.

### 3단계. 저장 경로를 상대 경로로
- 새로 쓰는 JSON에는 **프로젝트 폴더 기준 상대 경로**를 저장한다(`input/00001.jpg`, `work/masks/…`).
  읽을 때 프로젝트 폴더와 합쳐 절대 경로로 만든다.
- 대상: `session.json`(→`project.json`)의 `images[].input_path`와 같은 경로 필드, `regions.json`의 `mask_ref`,
  배경 복원 `state.json`의 패치 경로, 그 밖에 `grep -rl "/Users/" ~/ComicTranslator/projects | head`로 찾은 필드.
- 읽기 쪽은 절대 경로와 상대 경로를 모두 받아야 한다(이전 전 데이터 호환).
- 입력 캐시를 가리키는 링크는 **상대 링크**로 만든다(프로젝트 폴더에서 `../../cache/input/…`).
- 확인: 테스트 통과. 테스트용 데이터 홈(`COMIC_TRANSLATOR_HOME=$(mktemp -d)`)에서 새 프로젝트를 만들고 1장 분석.
- 커밋.

### 4단계. 데이터 이전 (스크립트 `scripts/migrate_workspace.py`)
**코드 변경이 아니라 사용자 데이터를 옮기는 단계다. 반드시 미리보기 → 백업 → 실행 순서를 지킨다.**

1. 미리보기(`--dry-run`, 기본값): 옮길 폴더, 고칠 JSON 파일 수와 필드, 다시 걸 링크 수, 예상 용량을 출력만 한다.
2. 백업: 같은 APFS 디스크라면 `cp -c`(복제, 거의 공간을 쓰지 않음)로 `temp_output`을 통째로 복제해 둔다.
   복제가 안 되면 사용자에게 백업 위치를 물어본다. **백업 없이 실행하지 않는다.**
3. 실행(`--apply`):
   - `temp_output/v2_sessions/*` → `~/ComicTranslator/projects/*`, `session.json` → `project.json`
   - `temp_output/v2_input_cache` → `cache/input`, `v2_cv_cache` → `cache/cv`, `v2_analysis_cache` → `cache/analysis`
   - `temp_output/v2_glossaries` → `glossaries`, `temp_output/image_generation_inbox`(아직 없으면 새로 만듦) → `inbox/image_generation`
   - JSON 안의 옛 절대 경로를 새 위치 기준 상대 경로로 바꾼다(3단계 규칙).
   - 입력 링크를 새 캐시 위치로 다시 건다.
   - 같은 디스크라 `mv`(이름 바꾸기)로 옮긴다. 복사 후 삭제하지 않는다.
4. 옛 데이터는 지우지 않고 `legacy/`로 옮긴다(4-3).
5. 확인 목록(5장)을 모두 통과하면 사용자에게 보고하고, 백업 삭제는 **사용자가 직접** 결정한다.

#### 4-3. legacy로 옮길 것
| 대상 | 위치 |
|---|---|
| `temp_output/Ore1`, `temp_output/Ore2`, `temp_output/test_v6_hybrid` | `legacy/temp_output/` |
| `temp_output/` 루트의 `debug_*` 이미지·JSON | `legacy/temp_output/debug/` |
| `output/` (Ore1·Ore2·Ore6 등 옛 결과, 2.7GB) | `legacy/output/` |
| 프로젝트 이름이 없고 같은 171장을 반복해 불러온 테스트 세션 | `legacy/projects_test/` |
| `proof/`의 git 제외 출력물 | `legacy/proof_outputs/` (테스트·문서 참조를 먼저 확인) |

- 테스트 세션 판별: `session.json`의 `project_name`이 비어 있고 같은 이미지 해시 목록을 가진 세션.
  최종 이미지가 있는 세션(`20260530_100023`, 142장)은 옮기지 말고 이름을 붙여 남길지 사용자에게 묻는다.
- `test_image/`, `test_image1/` → `samples/`. 테스트·문서가 이 경로를 참조하면 함께 고친다.

### 5단계. 비밀 파일
- `.env`와 `google-credentials.json`은 저장소 루트에 그대로 두고 git 제외 상태를 확인한다(이미 `.gitignore`에 있음).
- 값을 출력하거나 문서에 옮겨 적지 않는다.
- 맥 미니로 옮길 때는 이 두 파일만 따로 복사한다. 데이터 홈에 넣지 않는다(백업에 비밀이 섞이지 않게).

## 5. 확인 목록
- [ ] 전체 테스트 통과 개수가 0단계 이상
- [ ] `python app.py --no-browser`로 서버가 뜨고 시작 화면에 기존 프로젝트 목록이 보인다
- [ ] 프로젝트 2개(예: 사망플래그 7권, Ore_2)를 열어 페이지 이미지·분석 결과·수동 보정이 그대로 보인다
- [ ] 한 페이지에서 글자 입히기 렌더가 이전과 같은 결과를 낸다
- [ ] 배경 복원 패치가 있는 페이지가 그대로 합성된다
- [ ] 새 프로젝트를 만들어 1장 분석이 된다(새 위치에 상대 경로로 저장되는지)
- [ ] `grep -rl "temp_output" --include=*.py .`가 `archive/` 밖에서 나오지 않는다
- [ ] `~/ComicTranslator/projects` 안 JSON에 `/Users/` 절대 경로가 남지 않는다(링크 대상 포함)
- [ ] `/manual`, 이미지 생성, 에디터 MCP 브리지가 새 경로에서 동작한다

## 6. 되돌리기
- 코드: 단계별 커밋이므로 해당 커밋을 되돌린다.
- 데이터: `migrate_workspace.py --rollback`을 만들어 두거나, 0단계 백업 복제본을 `temp_output`으로 되돌린다.
  4단계 실행 전 백업이 없으면 실행하지 않는다.

## 7. 이번에 하지 않는 것 (후속 과제)
- **외장하드 zip 라이브러리 연동.** 지금 앱은 폴더·파일 불러오기만 있고 zip을 직접 읽지 않는다.
  다음 단계에서 `config.json`의 라이브러리 루트를 읽어 zip 목록을 보여 주고, 선택한 zip의 페이지를
  `cache/input/`에 풀어 프로젝트를 만든다. 프로젝트에는 원본을 `{라이브러리 ID, zip 상대 경로, 페이지 이름, sha256}`로
  기록해, 외장하드가 분리돼 있어도 프로젝트는 열리고 원본 재확인만 못 하게 한다.
- 코드 내부 이름(`session` → `project`)과 API 경로 변경.
- `archive/`(4.4GB) 정리.
- 프로젝트 메타를 SQLite로 옮기는 일. 프로젝트 수가 많아져 목록·검색이 느려지면 검토한다.

## 8. 작업 중 지킬 것
- 단계마다 테스트 → 커밋. 한 커밋에 코드 이름 변경과 데이터 이전을 섞지 않는다.
- 사용자 데이터를 지우는 명령(`rm -rf`)을 쓰지 않는다. 옮기거나 legacy로 보낸다.
- 경로를 바꾸는 테스트는 실제 데이터 홈을 쓰지 말고 `COMIC_TRANSLATOR_HOME`을 임시 폴더로 바꿔 돌린다.
- 다른 에이전트가 같은 저장소를 쓰고 있으면 시작 전에 작업을 멈추게 하고, 끝나면 새 경로를 알린다.
