# 원본 직접 참조와 호스트별 재연결

2026-10-21. 코드 저장소는 Developer, 데이터는 `~/ComicTranslator`에 유지한다.

## 적용 내용

- 일반 페이지는 원본 폴더를 직접 참조한다. 프로젝트의 기존 입력 파일명·페이지 ID·분석 경로는 유지하고 입력 별칭을 심볼릭 링크로 관리한다.
- 분할·크롭 결과는 프로젝트가 소유하는 실제 이미지로 보관한다.
- 브라우저 업로드는 원본 절대 경로를 알 수 없어 프로젝트에 파일을 보관한다. 복사 없는 입력은 서버의 원본 폴더 경로로 불러온다.
- 프로젝트에는 논리적 원본 폴더 ID와 상대 경로를 기록하고, 실제 원본 폴더 경로는 호스트별 설정에 저장한다.
- 홈/편집기의 ‘원본 연결’에서 맥 미니의 원본 경로를 입력하고 SHA-256 일치 미리보기를 확인한 뒤 연결한다. 파일명이 달라도 동일 내용이면 찾는다. 분할·크롭 페이지는 재연결하지 않는다.
- 변경된 원본에 기존 분석을 잘못 적용하지 않는다. 원본 해시가 다르면 유효한 기존 입력으로 대체하고, 대체 입력도 없으면 연결 누락으로 표시한다.
- 연결 변경 전 manifest와 링크 상태를 프로젝트의 `work/source_history`에 남긴다. 실패 시 입력 상태를 복원한다.
- MCP는 등록된 원본 페이지의 해시를 확인해 읽으며 원본 라이브러리 전체를 공개하지 않는다.

## 실제 이전 결과

활성 프로젝트 15개에서 일반 페이지 969장을 원본 참조로 전환하고 분할·크롭 이미지 165장은 프로젝트 내부 파일로 유지했다. 연결 누락은 없다. 현재 맥북에서는 데이터 폴더의 samples를 원본으로 연결했으며, 맥 미니에서는 실제 만화 원본 폴더로 다시 연결하면 된다.

이전 전후 비교: CV 캐시 726개, 분석 캐시 12,311개, 최종 이미지 439개의 SHA-256이 모두 동일하다. 원본 파일 1,913개의 크기와 수정 시각도 그대로다. 유료 분석이나 이미지 생성은 실행하지 않았다.

`cache/input`은 삭제하지 않았다. 기존 프로젝트와 보관 프로젝트의 참조, 원본 미연결 시 예비 입력으로 남긴다. 앞으로 일반 경로 입력에 대해 새 복사본을 만들지 않는다. 수동 심볼릭 링크만으로 관리하기보다 앱이 링크와 원본 참조 정보를 함께 관리한다.

## 검증

- 원본 직접 참조·외부 파일 접근 제한·삭제 시 원본 보존·해시 불일치·실패 복원·호스트별 경로 변경·이전 재실행 테스트.
- headless 브라우저에서 실제 170장 해시 미리보기 확인. 연결 적용 클릭은 모의 응답으로 검증해 실제 프로젝트를 변경하지 않음.
- 실제 프로젝트 MCP 원본 읽기 확인.
