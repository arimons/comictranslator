# 저장소 구조 정리 결과

## 적용한 변경

- 실행 파일 `app.py`, 화면 빌드 `web/`, 보조 실행기 `scripts/`로 이동했다.
- `pipeline/paths.py`에서 코드·데이터 위치를 정의한다. 기본 데이터 홈은 `~/ComicTranslator`다.
- manifest는 `project.json`으로 저장하고, `session.json` 읽기 호환을 유지한다.
- 프로젝트 JSON은 프로젝트 기준 상대 경로를 저장한다. 실행 시 경로를 해석한다.
- 입력과 분석 파일의 링크는 상대 링크다. 임시 분석 결과를 복사할 때도 저장 경계에서 상대 경로를 적용한다.
- 외부 원본은 수정하지 않는다. 입력은 cache/input에 작업 사본을 만들고 프로젝트 input에서 참조한다.
- 코드를 맥 미니로 옮겨도 같은 코드 폴더 이름이나 사용자명이 필요하지 않다.
- MCP 로컬 설정은 새 scripts 실행기로 갱신했다. 맥 미니에서는 설정 스크립트를 다시 실행한다.

## 실제 데이터 이전

APFS 복제 백업: `~/ComicTranslator/backups/pre-migration-20261020_225331`.
백업은 삭제하지 않았다. 이동 기록·롤백 정보는 데이터 홈 `migration.json`에 있다.

- 약 17GB, 67,992개 파일, 8,417개 링크의 이전 계획을 확인하고 실행했다.
- 활성 프로젝트 15개를 projects에 보존했다.
- 이름 없는 동일 171장 반복 프로젝트 중 최종 출력이 없는 13개는 legacy/projects_test로 이동했다. 수동 가이드도 보존했다.
- 무명 프로젝트 20260530_100023은 출력 142장이 있어 활성 프로젝트로 보존했다. 이름은 바꾸지 않았다.
- Ore_2 프로젝트 20260530_144110은 170페이지 중 출력 146장이다.
- 전체 170장 출력이 있는 이전 Ore2 결과도 legacy/output/Ore2에 보존했다.
- 기존 proof 출력은 legacy/proof_outputs로 이동했고 proof/src의 소스는 저장소에 남겼다.
- archive 자체는 정리하지 않았다. 폐기된 실행기와 배치 이력만 그곳으로 이동했다.

## 검증

- 기준 테스트: 506개. 경로·백업·롤백·별칭 디렉터리·임시 JSON 복사 회귀 검증을 추가했다.
- 활성 프로젝트의 입력 1,134장 존재를 확인했다. 중복 보관 프로젝트까지 포함한 원래 입력 3,357장도 이전 직후 확인했다.
- 최종 출력 439장을 이전 전 백업과 SHA-256으로 비교하여 전부 동일했다.
- 프로젝트 JSON에 `/Users/` 절대 경로가 남지 않는지 검사했다.
- 유료 API 호출을 차단한 새 임시 프로젝트에서 기존 CV만 재사용하고 TG·영역 분석을 실행했다. 영역 5개가 생성됐다.
- 이전 전/후 JSON으로 같은 페이지를 렌더하여 픽셀이 동일한 것을 확인했다. 원래 최종 출력은 덮어쓰지 않았다.
- 실제 프로젝트의 배경 복원 state에는 확정 패치가 없었다. 복원 합성은 기존 엔진 테스트와 경로 회귀 검사로 확인한다.
- headless로 7권·Ore_2·3권 커버, 매뉴얼, 생성 후보 이미지를 조회했다. 쓰기 요청 없이 통과했다.
- MCP 실제 stdio 조회·이미지 반환도 확인했다.

기존 누락: 활성 프로젝트의 예전 regions JSON에 마스크 참조 1,398개가 이미 없었다. 이전 전 백업에도 파일이 없음을 대조했다.
이번 이전 때문에 사라진 입력·마스크·최종 출력은 검출되지 않았다. 오래된 마스크 재생성은 이번 경로 정리 범위에서 실행하지 않았다.
`proof/src/verify_storage_migration.py`, `check_storage_pipeline.py`, `check_storage_migration.js`로 재검증할 수 있다.

## 공개 저장소

과거 이력에서 `.env`가 추적됐던 것을 발견했다. 공개 전 원래 Git 이력을 로컬 bundle로 백업하고 공개 main 이력에서
해당 파일을 제거한다. 현재 `.env`와 google-credentials.json은 로컬에서 유지하며 Git 제외 상태를 확인한다.
이력 정리로 이전 커밋 해시는 달라질 수 있다. 작업 단계별 커밋은 유지한다. 원래 비밀 파일이 든 백업은 공개하지 않는다.

## Syncthing 확인 및 맥 미니

확인한 MacBook 설정은 ~/Developer와 ~/.claude만 동기화한다. Developer/.stignore_rules에서 이 프로젝트의
temp_output, output, proof, archive, test_image1을 명시적으로 제외하고 있다.
.venv 및 .git도 공통 제외 규칙에 있다. Git 제외 규칙과 Syncthing 제외 규칙은 서로 별개다.

따라서 기존 산출물의 맥 미니 수신을 가정하면 안 된다. 새 ~/ComicTranslator는 Developer 밖이라 현재 설정에서는 동기화되지 않는다.
실제 맥 미니의 수신 이력까지 확인한 것은 아니다. Syncthing 설정은 변경하지 않았다.

맥 미니 준비:

1. 동기화된 코드가 있다면 새 app.py와 web이 도착했는지 확인한다. Git 이력은 동기화되지 않으므로 필요하면 공개 저장소를 별도로 clone한다.
2. 전체 데이터 홈을 복사하거나 별도 Syncthing 폴더로 연결한다. projects + cache/input + glossaries는 반드시 같이 보존한다.
3. .venv는 해당 머신에서 생성하고 requirements.txt를 설치한다. frontend 소스를 다시 빌드하려면 npm ci, npm run build를 실행한다.
4. .env, Google 인증 JSON, Fonts의 사용자 폰트를 확인한다. 비밀 파일은 Git으로 전달하지 않는다.
5. `.venv/bin/python app.py --no-browser --port 7873`으로 실행한다. MCP는 scripts/configure_editor_mcp.py를 다시 실행한다.
6. 데이터 홈 백업은 작업 확인 후 별도로 결정한다. 원본 zip 직접 연결은 후속 과제다.
